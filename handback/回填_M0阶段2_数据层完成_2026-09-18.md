## B. 分辨率决策

### B.1 本阶段决策：**走 M0 §3.7 路线 B（C++ 结构体）** —— 用户 2026-09-18 明确拍板

**为什么必须重新决策**：路线 A（蓝图结构体）在**纯自动化**路径上走不通，有两条硬证据：

1. `UnrealEditor` 的 Slate UI **不暴露 UIA**（我 2026-09-12 实测：UIA 树里枚举不到任何 UnrealEditor 窗口），所以不能脚本化点击
2. Python **无法给 `UserDefinedStruct` 加字段** —— 实测 `UserDefinedStructEditorUtils` / `DataTableEditorUtils` 都未暴露；能 `create_asset` 出一个空结构体，但加不了变量
3. 且 `CSVImportFactory.cpp:260` 明确：自动导入时若 `ImportRowStruct` 为空 → **直接放弃**，没有任何"从表头自动建结构体"的路径

**路线 B 的成本已经归零**：M0 §3.7 反对 B 的理由是「走 B 就等于开了 C++ 模块，M0 不想面对的问题全回来」——但**冻结决策 #3 已把项目类型定为 C++**，模块与编译链路（93 秒）2026-09-12 就已验证通过。

**折中方案（已执行）**：**结构体用 C++（纯数据声明、零逻辑），M0 的行为内容仍全部用蓝图** —— 这正是 M0 §3.7 路线 B 描述的做法，不违背冻结决策 #4 的本意。

**建议文档 session**：M0 §3.7 的「决策建议：M0 走 A」需要加一句前提 —— **"若项目类型已是 C++，则 B 的增量成本≈0，且是可自动化的唯一路径"**。

### B.2 附带决策：结构体头文件由脚本生成，不手写

`ue5ops/gen_data_rows.py` 从 `data/ue_datatables/*.struct.txt` **自动生成** 9 个 USTRUCT / 79 个 UPROPERTY，产出 `AC6DataRows.h`（15,809 B，UTF-8 with BOM + CRLF）。
好处：`.struct.txt` 更新后重跑即可，不会手抄错字段名（UE 按列名匹配，错一个就导入失败）。

## C. 卡点

### C-1 ★★★ 导出器有一个 1 行 bug，静默丢 14 行数据（**本阶段最重要产出**）

| 项 | 内容 |
|---|---|
| **症状** | 8 张表导入后行数对不上：`DT_Attack` **712 → 699**（丢 13）、`DT_Bullet` **568 → 567**（丢 1）。**导入不报错为 0 时也会丢**，只有引擎日志里有 `LogCSVImportFactory: Duplicate row name '...'` |
| **根因（精确到行）** | `tools/export_ue_datatables.py` 第 185~190 行的「去重」：<br>`if nm in used:` —— **`used` 是大小写敏感的字典**<br>但 **UE 的 `FName` 行名是大小写不敏感的**。于是仅大小写不同的两个行名**双双通过导出器去重**，到 UE 导入时才撞车，后者被静默丢弃 |
| **丢的是什么** | 共 14 行：**11 组是数据完全相同的重复**（丢一行无损）；**3 组是真正不同的数据**：<br>· `Bullet`：`hand_gun`(Life=1) vs `Hand_gun`(Life=2.25)<br>· `AtkParam_Pc`：`PA_Breaker_Weak_Attack_1`(AtkPhys 1800/冲击 2000) vs `PA_Breaker_Weak_attack_1`(0/1600)<br>· `AtkParam_Pc`：`Beam_naginata_strong_attack`(冲击 4800) vs `Beam_Naginata_Strong_attack`(600) |
| **建议修法（1 行）** | 第 186 行改为对**小写键**去重：<br>`key = nm.lower()`<br>`if key in used:` … `used[key] += 1` … `nm = '%s_%d' % (nm, used[key])`<br>⚠️ **但只改这一处还不够** —— 见下一条 |
| **二次碰撞（我实测踩到）** | 我第一版只做「小写键去重」，结果把 `PA_Breaker_Weak_attack` 改成了 `PA_Breaker_Weak_attack_1`，**而文件里本来就有一行叫 `PA_Breaker_Weak_Attack_1`** → 又撞了。所以正确算法必须**先把所有原始名（小写）放进 reserved 集合，改名结果不得占用 reserved** |
| **稳健算法** | ```reserved = {n.lower() for n in names}```<br>```used = set()```<br>对每个名：若 `key not in used` → 原样保留并 `used.add(key)`；<br>否则从 `_1` 起找第一个 `cand` 使 `cand.lower() not in used and cand.lower() not in reserved` |
| **我的临时处置** | `tools/` 归文档 session，**我没改**。我在 `ue5ops/prepare_csv.py` 里做了等效修正，产出到 `<UE_PROJECTS>\AC6Proto\data\ue_datatables\`，并生成 `rename_report.csv`（14 条改名记录）供对账 |
| **验证** | 修正后 8/8 表 **行名大小写不敏感唯一**；重新导入 8/8 **0 Problems**，行数**逐张精确吻合**（712 / 568 / 23 / 121 / 284 / 24 / 19 / 1232） |
| **建议文档 session** | ① 修 `export_ue_datatables.py:186`；② 重导 `data/ue_datatables/`；③ **在 M0 §3.6 的「八条硬规则」第 6 条补一句**：*行名必须大小写不敏感唯一（UE 的 FName 不区分大小写）* —— 现在写的是"行名必须唯一"，没说清是哪种唯一 |

### C-2 ★★ M0 §3.6 有一处笔误：`HitStopTime` 应为 `HitStopType`

| 项 | 内容 |

### C-5 ☆ 两个 API 细节（会浪费半小时的）

| # | 坑 | 正解 |
|---|---|---|
| 1 | `unreal.load_object(None, "/Script/AC6Proto.FEquipParamBoosterRow")` 返回 `None` | **UE 会剥掉 USTRUCT 的 `F` 前缀** → 正确路径是 `/Script/AC6Proto.EquipParamBoosterRow` |
| 2 | `get_data_table_column_as_string(dt, col, row)` 报 `takes at most 2 arguments` | 签名是 **`(table, column)`，返回整列字符串数组**，顺序同 `get_data_table_row_names` |

### C-6 ☆ 脚本编码连环坑（本轮又踩了 4 次）

| 坑 | 现象 | 规避 |
|---|---|---|
| bash heredoc + Python 中文 + 反斜杠 | `\U` 触发 unicodeescape 报错 | 路径用正斜杠，或写外部文件再执行 |
| JS 模板字符串吃 `$` | shell 变量被 JS 插值 | 用数组 join 建命令，避开 `${}` |
| Python 正则写进文件变 `\\s` | 正则匹配 0 条 | 用 `chr(92)` 构造反斜杠 |
| `verify_doc.py` 输出 `✓` 报 GBK 错 | 不是校验失败 | 跑之前设 `PYTHONIOENCODING=utf-8` |
