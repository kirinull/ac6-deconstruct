# 回填 · M0 第 4 阶段：锁定 / 开火 / 命中 / 冲击(ACS) / 姿态崩溃（2026-09-19）

> **来源会话**：UE5 実操 session（`goal-e29084b5-…`，第 2 轮）
> **范围**：第 2 批「锁定 + 开火 + 命中 + 冲击/ACS/硬直」。
> **本文件只回填，不修改任何 `outputs/`、`tools/`、`docs/` 里的结论。**

## §0 一句话结论

**AC6 的「弹丸 → 攻击参数」那一跳打通了**：
`Bullet.atkId_Bullet`（数值 id）→ `AtkParam_Pc` 的行，
实测 568 个弹丸里 **556 个（97.9%）** 能解析，自证样例包括 `Proto_Vertical_missile → Proto_Vertical_missile` 这类同名回环。

整条玩法链在实机跑通并有逐项读数（§2）：
**开火 → 弹丸扫掠 → 命中 → 伤害 = `AtkPhys` × `PartsDamageRate` → 冲击累积 = `ImpactPower` → 打满 `Stability` → 姿态崩溃**。
轻武器（machine_gun，冲击 40）打崩中量靶要 **20 发**；重武器（bazooka，冲击 3000）**一发**。

顺带：**这段路上踩到 5 个静默失败**（§3），每一个都表现为"看着在跑、其实没生效"，没有一个是报错的。

## §1 打通的数据链（本次最重要的交付）

```
EquipParamWeapon.behaviorVariationId
        │
        ╳  ← 这一跳**仍然断着**（见 §6.1）
        ▼
   Bullet[行名]  ── atkId_Bullet (u32@4) ──▶  AtkParam_Pc 的行 id
        │                                              │
        │  DT_AttackIdMap[<id>].RowName                │
        └──────────────────────────────────────────────┘
        ▼
   AtkParam_Pc[行名].AtkPhys / ImpactPower / ResidualImpactPower / HitStopTime
```

### 1.1 缺的那一环：`AtkParam_Pc` 的行 id 没有出现在导出的 CSV 里

M0 的 CSV 用的是 paramdex 的**开发者名**当行名，**数值 id 没带出来**。
而 `Bullet.atkId_Bullet` 指向的正是那个数值 id —— 所以中间缺一张映射表。

**解决办法（不碰文档 session 的任何文件）**：
新增生成器 `ue5ops/build_combat_tables.py`，从 **raw `.param`** 直接重建两张**补充表**：

| 新表 | 行数 | 内容 | 为什么单独出表 |
|---|---:|---|---|
| `DT_AttackIdMap` | 712 | `Name`(=<十进制 id>) → `RowName`(=`AtkParam_Pc` 的行名) | 让 UE 侧一次 `FindRow` 就能解析，不用扫 712 行 |
| `DT_BulletCombat` | 568 | `AtkIdBullet` / `InitVellocityMS` / `MaxVellocityMS` / `LifeSec` / `DistM` / `GravityInMS2` / `GravityOutMS2` / `HitRadiusM` / `NumShoot` / `HomingAngleDPS` / `LockShootLimitAngH` / `LockShootLimitAngV` | M0 的精选用列集里**没有** `AtkIdBullet` 与初速，而这两条是开火链路的入口 |

**为什么走"补充表"而不是往 M0 的 CSV 里加列**：
`data/ue_datatables/*.csv` 归文档 session 的 `tools/export_ue_datatables.py` 维护，
加列会在下次重导出时**静默消失**。补充表由 `ue5ops/` 从 raw 参数直接重建，任何时候都能重跑，
两边互不覆盖。

### 1.2 id 从哪来（以及怎么防止错位）

raw `.param` 的 LONGDATA 行头里带 id（`4B id + 4B pad + 8B didx + 8B noff`），
而导出的 CSV 是**按 raw 行序**逐行写的 —— 所以两者行序一一对应。
脚本对此**显式校验**：`raw 行数 != CSV 行数` 或 `id 有重复` 就直接报错退出，不允许静默错位。

**自证抽样**（脚本每次跑都会打印）：

```
自证 Proto_Vertical_missile   atkId=3100      -> Proto_Vertical_missile
自证 Proto_2_stage_launch_missile  atkId=3110 -> Proto_2_stage_launch_missile
自证 machine_gun              atkId=5020000   -> machine_gun
自证 assault_rifle            atkId=5010000   -> assault_rifle
自证 bazooka                  atkId=5040000   -> bazooka
自证 grenade_rifle            atkId=5080000   -> grenade_rifle
自证 shotgun                  atkId=5050000   -> shotgun
```

（导弹/火箭/机炮这些"弹丸名 == 攻击名"的回环是**独立**的自证；
`Proto_Rifle_OLD → Proto_Bazooka` 这类则是原表里开发者名本身就没对齐，不是我们的映射错。）

### 1.3 偏移一律从 paramdex 读，不写字面量（这条是被 bug 逼出来的）

第一版 `build_combat_tables.py` 里的偏移是我**手写**的，写错了三个：

| 字段 | 我猜的偏移 | 真实偏移 | 后果 |
|---|---:|---:|---|
| `initVellocity` | 20 | **44** | 偏移 20 是 `life` —— **把"寿命"当成"初速"读了** |
| `hitRadius` | 84 | **76** | 读到别的字段 |
| `numShoot` | 90 | **144** | 同上 |
| `homingAngle` | 100 | **146** | 同上 |

现在脚本改成从 `Paramdex/AC6/Defs/BulletParam.xml` **按字段名取偏移**，
字段改名/改序时脚本会自己发现（找不到就 `sys.exit`），并且每次运行都把实际用的偏移打印出来：

```
列偏移（取自 paramdex）: atkId_Bullet@4, initVellocity@44, maxVellocity@56, life@20, dist@24,
    gravityInRange@32, gravityOutRange@36, hitRadius@76, numShoot@144, homingAngle@146,
    lockShootLimitAng@161, lockShootLimitAng_V@632
```

**独立健全性检查**：`shotgun.NumShoot = 8`（霰弹 8 发），
`machine_gun.NumShoot = 1` —— 与直觉一致；若偏移错位，这两个数不会这么正好。

## §3 这一段路上踩到的 5 个静默失败

全部是"不报错、结果错"的类型。按踩到的顺序：

### 3.1 根组件上 `SetRelativeLocation` = 把整个 Actor 传送走

靶子方块的原点在**几何中心**，要"底面贴地"就得给根加 +半高 的偏移。
我把方块直接当根，然后 `Body->SetRelativeLocation((0,0,+400))` —— 对根组件做这件事
**等于把 Actor 传送到 (0,0,400)**，出生点全丢。三个靶子叠在原点，间距全没了。

**修法**：根用一个纯 `USceneComponent`，方块挂上去再偏移。

### 3.2 `SpawnActor` 会立刻跑 `BeginPlay`，属性是"晚一步"设的

想给靶子指定护甲行/尺寸，`SpawnActor` 之后再赋值 —— 而尺寸与血量都在 `BeginPlay` 里应用。
结果是三个靶子长得一样、血量一样，**不报任何错**。

**修法**：`SpawnActorDeferred` + 赋值 + `FinishGameplayStatics::FinishSpawningActor`。

### 3.3 幽灵轴：某个轴卡在 +1.0，机体自己飞出场外

HUD 上的「原始输入」抓到过 `Up +1.0` 与 `W +1.0` 各一次 ——
**没有任何人按键**，机体却以 360 km/h 自己飞走，30 秒漂了 120 m。
本机枚举出 10 个 `HID-compliant game controller`（驱动残留的虚拟设备），但 UE 只注册了 KBM 一个输入设备。

**两处修法**：
① `MoveUp` 不再绑手柄扳机（扳机做升降本来也不是 AC6 的映射），代码侧阈值从 0.1 抬到 0.35；
② **重获窗口焦点时清空缓存的轴输入** —— UE 的 `bShouldFlushPressedKeysOnViewportFocusLost`
只清引擎自己的按键状态，清不到我们缓存到 Pawn 成员里的 IN 值。

### 3.4 炮口偏移造成系统性脱靶（339 发 0 命中）

白箱的两门炮在 `Y = ±260 cm`，而瞄准方向是按**机体中心**算的。
沿那个方向直射，到 180 m 处偏 2.6 m —— 而靶子半宽只有 1.5 m。
**实测：对着靶子连打 339 发，0 命中，不报任何错。**

**修法**：加**会聚点**（瞄准射线延伸 1 km 处，弹道从炮口指向会聚点）——
所有第三人称射击都这么做。同时接入 AC6 真正的机制：
`Bullet.lockShootLimitAng / _V`（**开火补正角锥**，本项目实测众数 15° / 15°），
锁定目标与弹道方向夹角落在角锥内时把弹丸折向目标。
这正是 P7 §2.3 说的「每把武器的补正角锥是它的隐性手感属性」。

### 3.5 瞄准点选了血条挂点（打在靶子头顶上方 1.5 m）

`GetBarAnchorWorld()` = 方块顶面 + 1.5 m（给 HUD 画血条用）。
我拿它当瞄准点 ⇒ 弹道从靶子头顶飞过去，**644 m 后才打中远处的掩体块**。

**修法**：拆成两个函数 —— `GetBarAnchorWorld()`（HUD）与 `GetAimPointWorld()`（几何中心，瞄准用）。
修完命中率 0 → 98.5%。

### 3.6 顺带：靶子摆在了射界上的关卡道具后面

`build_arena.py` 在原点四向 100 m 处放了 2×2×12 m 的黄色「原点标记」柱，
而 100 m 正好在机体与 `T2-c` 之间 —— 348 发全打在那根柱子上。
**修法**：三个靶子挪到 `Y ≠ 0` 的方位。

> 这六条其实是一类东西：**AC6 项目里最贵的 bug 不是崩溃，是"看起来在跑"**。
> 这也是为什么每一环都要在 HUD 上留下"值 ← 来源字段"的读数 —— 没有那个读数，
> 3.4 与 3.5 都只能靠猜。

## §5 验证工具：三个控制台变量（以及为什么必须有）

**背景（这是本次会话的硬限制，必须写清楚）**：
本机的自动化链路里，**合成键鼠事件送不进 UE**。
实测：鼠标"移动"能生效（因为 `SetCursorPos` 产生的是**真实** `WM_MOUSEMOVE`），
但 `SendInput` 合成的**按键与鼠标按键** UE 收不到 —— HUD 上「动作回调」恒为 0，
即使前台窗口确认就是游戏。

于是"开火 / 锁定"这两条玩法链路**没法靠脚本端到端验证**。为此加了三个 cvar，把玩法变成可脚本驱动的：

| cvar | 默认 | 作用 |
|---|---|---|
| `ac6.AutoFire` | 0 | 1 = 无视按键持续开火；**并且**在硬锁时把 `ControlRotation` 指向目标（自动瞄准） |
| `ac6.ForceHardLock` | 0 | 1 = 每帧强制硬锁到最近的软锁候选 |
| `ac6.Weapon` | 0 | 选第几个弹丸预设（0=machine_gun … 4=bazooka） |

默认全是 0，**完全不影响正常游玩**；也是以后回归测试的入口。

跑法：

```bash
"<UE_ENGINE>/Engine/Binaries/Win64/UnrealEditor.exe" \
  "<UE_PROJECTS>/AC6Proto/AC6Proto.uproject" -game -windowed -ResX=1280 -ResY=720 \
  -ExecCmds="ac6.AutoFire 1,ac6.ForceHardLock 1,ac6.Weapon 4"
```

**另外**：`_scratch/camdrive.ps1` 里的 `[I]::Click()`（左键）会**注入幽灵轴**（§3.3），
所以截图请用 `_scratch/shot_any.ps1`（只抢焦点、不点击）。这条也一并记在这里，免得下次重踩。

## §6 没做的 / 数据缺口

### 6.1 ★ 「武器 → 弹丸」这一跳仍然断着（要文档 session 定夺）

`EquipParamWeapon.behaviorVariationId`（如 TURNER = 10110）指向的**不是** `BehaviorParam` 的行 id，
也不是它的 `variationId` 字段（三种匹配都试过，全落空）。
`BehaviorParam` 的 `refId` 值域是 `85202000 / 90315000` 这类，落在另一个命名空间。

按 paramdex 的血统，中间应该还有一张 **`BehaviorVariationParam`**（武器 variationId → 行为 id 列表）。
**这张表没在导出集里**，我也没有在 raw 目录里确认它存在。

**当前绕法**：弹丸行名在 Pawn 上显式指定（`BulletPresets`），HUD 上标注这是缺口。
**恢复的办法**（建议下一批做）：确认 `BehaviorVariationParam` 是否存在 → 导出 →
把 `behaviorVariationId → BehaviorParam → bullet` 接上；顺带能拿到 **射速 `shootInterval`**。

### 6.2 射速目前不是数据（同上一条缺口）

`EquipParamWeapon.waitTimeForShoot` 在真实武器行上**全是 0**（只有 27/284 非零）。
AC6 真正的射速在 `BehaviorParam.shootInterval`（0.01~10 s），被 §6.1 挡住。
现在用可调的 `FireIntervalSec`（默认 0.10 s ≈ 600 RPM），HUD 上标注「非数据来源」。

### 6.3 冲击阈值还是单一值，不是阶梯

AC6 真正用的是 `DamageLevelConvThresholdParam` 的 **7 级阶梯**
`[150, 1600, 1600, 2000, 7500, 9000, 13000]`（P7 §8.1b），
以及攻击方的 `DamageLevelConvParam`（10 种 DL 阶梯，决定"这次命中算 DL 几"）。
两张表都**没导入**，所以这一版把 `EquipParamProtector.Stability` 直接当**单一阈值**用 ——
也就是 M0 §3.10 T2 靶的简化模型。HUD 上如实标注。

### 6.4 部位倍率 / 防御减免 / 伤害衰减都没做

| 缺的东西 | 在哪张表 | 影响 |
|---|---|---|
| `NpcPartsParam.addImpactRate`（打不同部位给不同冲击倍数，实测 1.0 / 0.25 / 0.0） | 未导入 | 现在是全局倍率 `AddImpactRate = 1.0`（C 级近似） |
| `EquipParamProtector.DefensePhysics` 与防御减免曲线 | 表里有，**精选用列集里没有这一列** | 现在伤害 = `AtkPhys` × `PartsDamageRate`，**不做减免** |
| `DistAtkPowerRateCalcGraphParam`（射程外伤害衰减） | 未导入 | 300 m 外伤害不衰减 |
| `PlayerFadeDist = 12 m` 的模型淡出 | 已知（LockCamParam） | AB 相机贴到 9 m 时机体占屏很大，归第 3 批 |

### 6.5 姿态崩溃时长是 M0 规格值，不是 AC6 数据

用的是 M0 手写的 `GameSettings.StaggerDurationSec = 1.2 s`。
AC6 的真实时长在 `SpEffectParam` 的 DL4 行（4120 行表，未导入）。
**优先读 `DT_GameSettings`，勾 `bOverrideGameSettings` 才用 Pawn 上的本地值** ——
这样「改 CSV → 生效 ≤15 s」的验收路径走的是数据表，也是第 3 批面板要驱动的那条路。

### 6.6 第 1 批遗留（未变）

- 相机自身高度偏移与初始俯角仍未按 P1 §10.3 的像素量测法标定。
- `NormalMoveSpeedRatio = 0.45` 仍是占位。
- `ChrTransChaseRate*` 的单位仍是 C 级推定（按 F30 = 帧@30fps 解释）。
- `camLookdownOffsetY` 仍然缺（导出链单点丢失，见上一份回填 §5.1）。

## §7 复现命令

```bash

powershell -NoProfile -Command "Get-Process UnrealEditor,UnrealEditor-Cmd,LiveCodingConsole -EA SilentlyContinue | Stop-Process -Force"

# 1) 重建两张补充表 -> 同步到工程 -> 生成 C++ 结构体
cd <repo>
python ue5ops/build_combat_tables.py     # 预期：AttackIdMap 712 行；BulletCombat 568 行，atkId 命中 97.9%
python ue5ops/prepare_csv.py
python ue5ops/gen_data_rows.py           # 预期：解析到 17 张表
```

| 结论 | 等级 | 依据 |
|---|---|---|
| `Bullet.atkId_Bullet` → `AtkParam_Pc` 行 id（数值 id，行序对应） | **A/B** | 97.9% 解析率 + 多条同名回环自证；行数校验 712=712 |
