## 0. 角色边界（谁干什么）

| | **文档 session**（当前维护者） | **UE5 实操 session**（你） |
|---|---|---|
| 职责 | 文档、数据、校验脚本、任务书、口径统一 | 在引擎里真的把东西做出来 |
| 会做的 | 写/改 `.md`、写 `tools/*.py`、跑 `verify_doc.py`、导出 CSV、核对口径 | 建项目、建 Struct/DataTable、搭关卡、连蓝图、写 C++、打包、录视频 |
| **不会做的** | ❌ 不打开编辑器、❌ 不建资产、❌ 不写游戏逻辑代码 | ❌ 不改 `docs/` 的结论、❌ 不改 `tools/` 的解析逻辑 |
| 交付物 | 文档 + 数据 + 任务书 | 能跑的东西 + **回填报告**（见 §7） |

**为什么这样分**：文档要的是**口径一致与可复现**，实操要的是**快速迭代**。混在一起，两边都会变慢，而且文档的"实测"会变成"我听说"。

> **有冲突时**：实操里量到的真实数据 **>** 文档里写的预期值。**以实测为准，然后回填给文档 session 修正。**（这正是本项目"证据分级 A/B/C/D"纪律的落地方式）

**端到端工具链已验证过**：UBT 生成工程文件 9.2 s → 编译 `ToolchainCheckEditor Win64 Development` 79 s，两次都 `Result: Succeeded`。

### ⚠️ 三个会咬你的环境事实

**① 从某些终端启动 VS2022 会直接崩溃**

症状：`System.ArgumentException: 已添加项。字典中的关键字:"no_proxy"所添加的关键字:"NO_PROXY"`

原因：某些终端（如 DSH 的 bash）会注入大小写重复的代理变量，.NET 建环境字典时炸掉。
**桌面/开始菜单双击是正常的**；要从终端启动就用这个包装脚本：

```powershell
powershell -NoProfile -File <repo>\tools\launch_net_clean.ps1 `
  -Exe '<VS2022>\Common7\IDE\devenv.exe'
```

自检（报 `已添加项` 就是中招）：`Get-ChildItem Env: | Where-Object { $_.Name -match 'proxy' }`
→ 全文见 M0 **附三 · 坑 0**

**② UE 5.8 默认用 VS2026 编译，不是 VS2022**

UBT 自动选中 `C:\Program Files (x86)\Microsoft Visual Studio\18\BuildTools`（MSVC 14.50）。
强制用 VS2022 要加参数：`-Compiler=VisualStudio2022`。**两者共存无冲突。**

**③ UE 5.6 起移除了 Starter Content**

创建对话框里**没有**「初学者内容包」勾选框 —— 这是对的，不是装坏了。
源码证据：`TemplateProjectDefs.h:108` → `StarterContent UE_DEPRECATED(5.6, ...)`
占位资产改用 `Engine/BasicShapes/`（含 `BasicShapeMaterial`，带 Vector + Scalar 参数）。

## 7. ★ 回填协议（你怎么把结果交回给文档 session）

**这是两个 session 之间唯一的接口。** 你每完成一个阶段，按下面格式回填一次；文档 session 会据此修正文档。

### 7.1 必须回填的四类

| 类别 | 具体内容 | 为什么要 |
|---|---|---|
| **A. 实测值** | M0 §4 那 18 条数值，你在编辑器里实际看到的值（与文档不符的优先） | 文档里是"从 param 表解析出来的"，**不等于编辑器里跑出来的** |
| **B. 分辨率决策** | M0 §3.7 给了 **两套 Struct 方案**，你用了哪套？为什么？ | 文档要收敛成一套推荐 |
| **C. 卡点与解法** | 任何文档没预警的报错、任何"文档说的按钮找不到" | 直接进 M0 §1.7 / §5.2 |
| **D. 验收结果** | ≤15 s 验收线是否达成？实测多少秒？`stat fps` / `stat unit` 实际数字 | M0 §6 的判据需要真实数据 |

### 7.2 回填格式（照抄这个模板）

**写到哪**：`<repo>\handback\回填_<阶段名>_<YYYY-MM-DD>.md`
（一阶段一个文件，不要追加到同一份里；这个目录是文档 session 唯一会去取件的地方）

> ⚠️ 下面**全是占位符**（`‹›` 里的才是你要填的），不是真实测量值。
> **不要照抄数字** —— 本项目的纪律是"没量过就不写数"。

```markdown
## 回填 · ‹阶段名› · ‹YYYY-MM-DD›

### A. 实测值
| 项 | 文档预期 | 实测 | 差异说明 |
|---|---|---|---|
| ‹字段/表名› | ‹M0 §4 写的值› | ‹你实际看到的› | ‹一致 / 不一致，为什么› |

### B. 决策
- Struct 方案：用了「路线 A / 路线 B」（M0 §3.7 给了两套），理由：‹…›

### C. 卡点
| 症状 | 文档是否预警 | 实际解法 |
|---|---|---|
| ‹报错原文› | ‹✅ M0 §x.y / ❌ 未预警› | ‹怎么解决的› |

### D. 验收
- CSV→生效：**实测 ‹N› 秒**（验收线 ≤15 s；Tier 2 ≤5 s 加分）
- `stat fps`：**‹N›**
- `stat unit`：Frame ‹N›ms / Game ‹N›ms / Draw ‹N›ms / GPU ‹N›ms
- 未通过项：‹无 / 列出›
```

### 7.3 文档 session 收到后会做什么

1. 用 `tools/check_field.py` / `check_bit.py` **独立复核**你的实测值是否与 param 数据自洽
2. 不一致 → 判断是"文档错"还是"实操环境差异"，**改文档并标注证据等级**
3. 新增/修改的结论 → 写进 `tools/verify_doc.py` 断言（**能自动复核的才算 A 级**）
4. 更新 `README.md` 的进度表与主文档修订记录

## 8. 纪律（本项目特有，违反会导致文档退化成"我听说"）

| 规则 | 说明 |
|---|---|
| **证据分级 A/B/C/D** | A = 本机可复现；B = 本机可复现的统计；C = 未验证的说法；D = 不许当结论。**B 级必须能本机复现**，否则降 C |
| **凡"全表/全部"类断言，必须跑全量统计** | 不允许目测抽样（本项目**已经因此翻车 4 次**） |
| **统计口径必须写清** | 同一个字段，剔除哨兵值(−1)/仅正数/含 −1，会得出**三个不同的中位数** |
| **位域必须按位读** | 按整字节读会得出**完全相反**的结论（`isEnableAutoStagger` 类字段） |
| **禁止为了让测试通过而降低断言** | 断言失败 → 先查是自己错还是文档错 |
