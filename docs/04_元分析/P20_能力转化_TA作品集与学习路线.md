### 1.1 这张表的三个结论

1. **你的 P0 不再是"学更多数据知识"，而是"把数据知识接到引擎上"**——第 1、3、11、15、16 项（UE5 入门 / UE5 C++ / 材质 / 动画蓝图 / UMG）是分水岭。**其中第 1 项是最硬的**：UE5 = 0 意味着前两周你几乎产不出"机甲内容"。

## 2. 12 周路线（按 52 人日新预算重排）

> **预算口径**：35 h/周 ≈ **4.4 人日/周** → 12 周 = **420 h ≈ 52 人日**（1 人日 = 8 h）。

### 2.0 为什么沿用 12 周，以及它与投递窗口的关系（v2 新增）

12 周本身是合理的（足够从 UE5 = 0 做到"能玩 + 一份交付包"），但**它不一定对齐你的投递窗口**——这一条 v1 完全没提：

| 若你的毕业时间是… | 秋招主窗口 | 12 周后（2026-12-06）你处在… | 建议 |
|---|---|---|---|
| **2027 年毕业（最常见的默认假设）** | 2026-08 ~ 2026-11 | **秋招主窗口已关闭**，只剩补录 + 日常实习 | 12 周成果的真实用途是 **11~12 月补录 / 日常实习 / 2027 春招（2~4 月）主作品集**。→ **把 12 周当"作品集 v1"，把 12~16 周（含寒假）当"v2 + 春招冲刺"**；**不要为了赶秋招尾巴砍掉项目 A** |
| 大三 / 更晚毕业 | 2027 秋 | 距秋招还有 10 个月 | 12 周只做 **A + B**，节奏可放松，C 延后 |
| 已毕业 / 待业 | — | 随时可投 | 35 h/周即"半全职"，本方案直接可用；**投递不要等 12 周做完**，第 4 周就把"能玩 v0.1 + 拆解文档"投出去试水 |

### 2.3 三条贯穿纪律（v1 纪律保留，第 1 条加强）

1. **每周必须有一次 commit 记录"本周产出物"**，产出物进 `docs/` 或 `Content/`——**不是留在聊天记录里**。W1 的第 3 个验收（仓库 + README）就是为这条服务的。
2. **每个数字都要能现场复现**（§5 给了 5 条命令，全部已实跑）；做不到就不许写进作品集。
3. **不复制资产**：模型、贴图、音效全部自制或用 CC0；作品集统一注明"**机制分析与技术复刻，非资产复制**"。

### 2.4 每周 35 h 的时间切法（v2 新增 · 新手最容易在"学"上超支）

| 时段 | 时长 | 内容 | 硬约束 |
|---|---|---|---|
| 学 | **≤ 10 h** | 看文档 / 教程 / 拆别人工程 | **不允许"学完再动手"**；每个知识点必须在当周产出物里用上，否则当周就砍掉 |
| 做 | **≥ 20 h** | 直接产出可展示的东西 | 每周五必须有一次"能跑起来的提交" |
| 写与录 | **5 h** | 参数表 / 规格书 / 录像 / commit 整理 | 不写 = 没做（面试官看不到你的 PIE 窗口） |

> **为什么写这一条**：UE5 = 0 的人最常见的失败模式不是"学不会"，而是**"教程看了 40 小时，产出为零"**。这条规则把学习时间硬性锁在 1/3 以内。

## 3. 作品集项目设计（3 个，难度递进 · 按 52 人日重算）

> **人日换算**：1 人日 = 8 h；35 h/周 ≈ **4.4 人日/周**。
> **总预算 52 人日**：A ≈ 16~20、B ≈ 16~22、C ≈ 12~16 → 合计 **44~58**，**与预算闭合**（v1 的 50~72 人日 + C2 再加 30~45，在 41 人日预算下**数学上不闭合**，这是 v1 最大的内部矛盾）。
> **顺序不可换**：A → B → C。**C 是 A/B 的副产品**，不是第三件独立作品。

## 5. 五个可讲的拆解故事（每个 60 秒 · 全部已实跑）

> **用法**：面试时不要背结论，**背"我怎么做出来的"**。每个故事最后都留一句"**要不要我现在跑一遍？**"——这是你和 90% 应届生不一样的地方。
> **前置**：命令都在项目根目录 `<repo>` 执行；先跑 `python tools/verify_doc.py` → **203/203 通过**（这是你的"开场白证据"）。
> **下面每条命令的输出现场粘贴自本机实跑**（2026-09-11），不是回忆。

### 故事 ①「顿帧只用于近战」—— 反直觉的发现

- **现象**：几乎所有人的直觉是"打击感 = 顿帧"，动作游戏里每一下都要顿 30~80 ms。
- **我的分析**：如果 AC6 也这么干，`AtkParam` 里应该满地都是顿帧值。所以我先统计它到底有多少行设了顿帧。
- **我如何验证**：

  ```bash
  cd <repo>
  python tools/verify_doc.py                       # 203/203 通过（含 hitStopTime 的分部断言）
  python tools/check_field.py AtkParam_Pc AtkParam hitStopTime
  ```

  实测输出：

  ```
  AtkParam_Pc.hitStopTime  712 行 / 行宽 1040 B / 偏移 24 / 类型 f32
    非零 45 行 | min=0.000 max=0.120 中位(全体)=0.000 中位(非零)=0.050
    唯一值: [0.0, 0.05, 0.07, 0.10, 0.12]
    非零行号: [163, 501, 503, 510, 511, 512, ... 559, 560, 562]
  ```

  **712 行里只有 45 行非零；取值只有 4 个（0.05 / 0.07 / 0.10 / 0.12 秒）；非零行号集中在 501~562 这个连续簇（另有一个孤立的 163）。枪械/子弹攻击完全不设顿帧。**
- **它靠什么替代**：命中音效并发上限（半径 50 m 内 = 1 个）、多段命中音效间隔 0.2 s、伤害数字合并窗 0.5 s、命中标记 1.0 s（**B**）。
- **我学到的能力**：**不要用"行业惯例"替代统计**；反馈设计的敌人不是"不够强"，是"**信道饱和**"。
- **追问预案**："那你怎么确定 501~562 就是近战？" → 答：我用 `Developer Names` 目录的行名文件对照，并检查 `AttackActionParam` 的互斥槽位；这是交叉验证，不是猜。

### 故事 ②「机甲的'重'来自角速度上限，而不是加速度（但坦克例外）」

- **现象**：大家默认"重装机转得慢"是因为它**加速慢**。
- **我的分析**：我把转向表的两个字段**分别**统计（注意口径），再顺着护甲表的外键去找"腿型 → 转向参数行"的关系。
- **我如何验证**：

  ```bash
  python tools/check_field.py ChrActTurnParam ChrActTurnParam baseTurnSpeedDPS
  # 非零 201 行 | 中位(全体)=320 | 中位(非零)=400   ← 口径差异，必须说清
  python tools/check_field.py ChrActTurnParam ChrActTurnParam turnAccelDPSS
  # 中位 = 9999999（≈瞬时）
  ```

  再查 `EquipParamProtector.legs_TurnParamId`（**B**）：

  | 腿型 | 转向参数行 | 角速度 | 角加速度 |
  |---|---|---|---|
  | 二足 / 逆关节 / 四足 | `10000000` / `11000000` / `12000000` | **360 deg/s** | **9999999（≈瞬时）** |
  | 坦克 | `13000000` / `13100000` / `13200000` | **230 / 320 / 400 deg/s** | **230 / 350 / 450 deg/s²** |

  → **转向是"腿型决定的离散档位"，不是重量连续函数**；而"重"有**两种来源**：大多数腿型靠**低角速度上限**，**坦克腿额外有真实角加速度**（所以它"转起来像开船"）。**复刻时这两种手感要分别实现**。
- **顺带一个可讲的细节**：瞄准模式 `lookTargetModeTurnSpeedDPS` 中位 **999 deg/s**，是基准的 **2.5 倍**，且有"角度差 < 90° 时降到 480"的分支（**B**）→ **AC6 把"机体朝向（慢，有重量感）"和"武器/上身瞄准（快，保证可玩）"分开了**，这就是"机甲转不动但射击不掉手感"的答案。
- **我学到的能力**：**"重"是一个可调参数的选择，不是物理仿真的副产品**；而且我养成了先声明统计口径的习惯（全体中位 320 vs 有效行中位 400）。
- **追问预案**："为什么角加速度给无穷大反而更真实？" → 答：因为玩家能**持续**感受到"转不过来"，而不是只在起步那一下慢；实测数据支持这个选择。

### 故事 ③「位域读取陷阱 —— 我差点得出完全相反的结论」

- **现象**：我想验证"AC6 有没有无锁自动捕捉（不用锁定也能自动追击）"，第一次读出来的结果是 **568/568 全部置位**。
- **我的分析**：全表 100% 置位的字段通常意味着"**我读错了**"，而不是"设计如此"。我回去看字段定义，发现它是 `u8` 的 **bit4 位域**。
- **我如何验证**：

  ```bash
  python tools/check_bit.py Bullet BulletParam isEnableAutoHoming
  ```

  实测输出（同一份数据、同一个字节，两种读法）：

  ```
  Bullet.isEnableAutoHoming  位域=(172, 4, 1)  类型=u8 偏移=172
    按整字节非零: 568/568
    按位读取置位: 0/568
  ```

  **结论完全反转：AC6 根本不做无锁自动捕捉（0/568）。**
- **我学到的能力**：**"全表 100%"是可疑信号，不是结论**；凡字段名带 `:N` 的，必须按位读取。我把这条写进了流程检查清单，并且**把正确读法做成了工具**（`check_bit.py`）——这样别人也能证伪我。
- **追问预案**："你怎么保证位序没错？" → 答：`paramdex` 定义给出 `(字节偏移 172, bit 起点 4, 宽度 1)`；我用同一个位域在另一张表上做了反向验证，并把这条写成了 `verify_doc.py` 的断言，任何人跑一遍都能证伪我。

### 故事 ④「减伤公式无法本地验证 → 我把它降级，而不是硬讲」

- **现象**：社区有一套流传很广的减伤公式（含"防御 1227"这个数），能被社区实测复算到误差 0.1%，看起来非常可信。
- **我的分析**：我要把它写进实施文档当"可直接用"，所以先做了一件"多余"的事——**在本地 257 张表里找 1227**。
- **我如何验证**：

  ```bash
  python tools/verify_doc.py      # 203/203 通过，其中含"NpcParam 内不含 1227"这类断言
  ```

  结果：**按字段语义读，零命中**。我一开始用裸字节扫描，得到 7 张表"命中"——但逐条查位置后发现**全部落在数据区之前（表头 / 行头 / 字符串表），与行首不对齐**，是**假阳性**。也就是说：**"零命中"这个结论本身依赖口径**，必须说清是"按字段值口径"。
- **我做了三件事**：① 把公式从"B 级可直接用"**降级为 C 级**；② 补充 AC6 **真正的**防御机制（格挡减伤率 **74~100%**、AP、姿态稳定三件套，**B**）；③ 写下"请自己用训练场取 5 组 (防御, 伤害) **拟合你自己的中性点**"。
- **我学到的能力**：**"社区都这么说"不等于"能在你的数据里验证"**；**把不可验证的东西降级，比讲一个漂亮但站不住的结论更值钱**。这条后来被我自己的对抗审查报告采纳（审查共发现 3 处高严重度问题，都是我自己的）。
- **追问预案**："那你为什么不干脆删掉这个公式？" → 答：因为它的**结构**（线性系数乘法、存在一个中性点）是有设计价值的，错的是"1000 这个具体常数"；我保留结构、标注常数待定，并给出拟合方法。

### 故事 ⑤「Jiggler 双求解器 —— 参数可以照抄，但倍数不能照吹」

- **现象**：文档里有一条很漂亮的结论："Jiggler 的平移力是旋转力的 **5 倍**，所以零件主要是被甩出去的"。我准备把它当成面试的黄金句。
- **我的分析**：既然要吹，就要吹得住。我决定自己把这两个参数各跑一遍。
- **我如何验证**：

  ```bash
  python tools/check_field.py JigglerBehaviorParam JigglerBehaviorParam rotAccelScaleX
  # 49 行 / 非零 47 行 | 中位(全体)=20 | max=115
  python tools/check_field.py JigglerBehaviorSlideParam JigglerBehaviorSlideParam moveAccelScaleX
  # 33 行 / 非零 22 行 | 中位(非零)=330 | max=580
  ```

  结果：**"5 倍"是"上限比"（580 / 115 ≈ 5.0）**；按非零中位算是 **330 / 20 = 16.5 倍**。而且两个参数来自**两张不同的表**（`JigglerBehaviorParam` 行宽 64 B vs `JigglerBehaviorSlideParam` 行宽 80 B），**量纲可能不同**——原报告自己标了 **C 级**并提示"两表量纲可能不同"。
- **我改成**：**方向性结论保留**（平移力**显著大于**旋转力，说明零件主要是"被甩出去"而不是"被转过去"），**倍数标 C 级，不许当精确数字讲**；并写清"要算准比值必须**逐行配对** `behaviorParamId` ↔ `behaviorSlideParamId`"——这是下一步可做的验证，也是我能对面试官说"我知道这份结论的边界在哪"的证据。
- **我学到的能力**：**能照抄的是量级，不能照抄的是"我算出来的"这句话**。参数照抄能让原型少走 3 周弯路（生效区间 **50~300 m/s²**、旋转力中位 ~20、阻尼 **~5**、限位反弹 **0.1~0.2**、角度硬限位 **±45°**、位置硬限位 **±2.0 m**，全是 **B 级可用值**），但对外讲时必须区分"实测"与"上限比"。
- **追问预案**："那你怎么确定这些参数真能做出机甲感？" → 答：我不确定，所以我做了 **A/B 并排视频 + 标定台**；这正是我作品集项目 B 的由来。

### 6.1 三个最大卡点与应对

#### 卡点 A（v2 新增，头号）：**时间会被"学习"吃掉 —— 你不是学不会，是学不完**

- **难点在哪**：§1 的 P0 项学习成本合计 **≈ 386 h ≈ 48 人日**，而总预算 52 人日。**如果按"先学完再做"，你会在第 11.5 周才开工**。这是 UE5 = 0 的人最典型的死法：教程看了 200 小时，GitHub 上一个 commit 都没有。
- **应对（三条，硬性）**：
  1. **学习时间硬锁在每周 ≤10 h**（≈ 1/3），其余 ≥25 h 必须产出可展示的东西（§2.4）。
  2. **每个知识点必须在当周产出物里被用上**——学 UMG 是为了显示 EN 条，学 UV 是为了给自制机甲件上贴图，学 Insights 是为了交 60 fps 报告。**用不上的知识点当周就砍掉**。
  3. **每周五必须有一次"能跑起来的提交"**；做不到就在当周砍范围（不是加班补）。

#### 卡点 B：**偏科 + "策划入门"这条路会被两边面试官打折**

- **难点在哪**：TA 岗（尤其校招/实习）筛选标准是"DCC + 引擎 + 作品集 + 画面"，而你的简历会是"系统/数值/战斗策划"。结果是：**TA 岗觉得你没做过美术，策划岗觉得你心不在此**。现实里"策划转 TA"多数发生在**入行 1~3 年后的内部转岗**，且窗口不掌握在你手里。**叠加 UE5 = 0，你在校招 TA 岗的正面胜率不高——这是要承认的。**
- **应对（四条）**：
  1. **别只投"TA"这一个名字**：同时投 **技术策划 / 工具向策划 / 关卡策划（会脚本）**——这是"策划入门 + 技术能力"唯一能被同时承认的交集岗，也是最短的桥。
  2. **简历写两版**：TA 版把"数据管线 + 规格书 + 引擎原型"提到最前；策划版把"从 257 张表反推系统架构 + 可复现验证流程"提到最前。**同一套材料，两种叙事**。
  3. **把"我最懂策划要什么"变成卖点**：调参面板、规格书、热力图，全部是"**给策划用**"的交付物。这在 TA 面试里是加分项，因为大量 TA 技术强但沟通差。
  4. **接受"不完美"**：3 个月做不出 12 槽位和好看的美术。**做 6 槽位、3 把武器、1 个站桩靶 + 1 个会出招的敌人**；把系统做穿比把内容做多值钱。

#### 卡点 C：**归因风险 —— "这是不是 AI 做的？"**

- **难点在哪**：这个拆解项目 AI 参与度很高（这是事实，不要掩饰）。面试官只要问三个"为什么"就能分清：能复现的人讲证据链，不能的人只会背结论。**一旦被贴上"AI 代做"标签，你唯一的护城河会瞬间变成负资产。**
- **应对（五条）**：

### C. 两个现场演示脚本源码

> **本版已把它们落盘为真实文件**（v1 只给了源码让你自己存）：
> `tools/check_field.py` 与 `tools/check_bit.py`——**附录 B 里的命令可以直接跑**，这就是"现场演示"的底气。

`tools/check_field.py` —— 任意表的任意字段统计（**同时打印"全体"与"非零"两种中位口径**，这是防口径陷阱的关键）：

```python
# 用法: python tools/check_field.py <表名> <paramdef名> <字段名>
# 例:   python tools/check_field.py AtkParam_Pc AtkParam hitStopTime
import importlib.util as I, os, struct, statistics as st, sys

HERE = os.path.dirname(os.path.abspath(__file__))
pi = I.module_from_spec(s := I.spec_from_file_location('pi', os.path.join(HERE, 'param_inspect.py')))
s.loader.exec_module(pi)
pf = I.module_from_spec(s2 := I.spec_from_file_location('pf', os.path.join(HERE, 'paramdex_fields.py')))
s2.loader.exec_module(pf)

tbl, pdname, field = sys.argv[1], sys.argv[2], sys.argv[3]
p = pi.parse(os.path.join(pi.ROOTS['van'], tbl + '.param'))
FL, _ = pf.fields_of(os.path.join(pf.PD, 'Defs', pdname + '.xml'))
f = {n.split(':')[0].split('[')[0]: (o, t) for o, t, n, d in FL}
o, t = f[field]
v = [struct.unpack_from('<' + pf.TYPE_FMT[t], p['b'], p['datastart'] + i * p['rowsize'] + o)[0]
     for i in range(p['rowcount'])]
nz = [x for x in v if x]
print('%s.%s  %d 行 / 行宽 %d B / 偏移 %d / 类型 %s'
      % (tbl, field, p['rowcount'], p['rowsize'], o, t))
print('  非零 %d 行 | min=%.3f max=%.3f 中位(全体)=%.3f 中位(非零)=%.3f'
      % (len(nz), min(v), max(v), st.median(v), st.median(nz) if nz else 0))
if len(set(v)) <= 12:
    print('  唯一值: %s' % sorted(set(v)))
if nz and len(nz) <= 80:
    print('  非零行号: %s' % [i for i, x in enumerate(v) if x])
```

`tools/check_bit.py` —— **位域字段专用**（故事 ③ 的现场演示工具）：

```python
# 用法: python tools/check_bit.py <表名> <paramdef名> <字段名>
# 例:   python tools/check_bit.py Bullet BulletParam isEnableAutoHoming
import importlib.util as I, os, struct, sys

HERE = os.path.dirname(os.path.abspath(__file__))
pi = I.module_from_spec(s := I.spec_from_file_location('pi', os.path.join(HERE, 'param_inspect.py')))
s.loader.exec_module(pi)
pf = I.module_from_spec(s2 := I.spec_from_file_location('pf', os.path.join(HERE, 'paramdex_fields.py')))
s2.loader.exec_module(pf)

tbl, pdname, field = sys.argv[1], sys.argv[2], sys.argv[3]
p = pi.parse(os.path.join(pi.ROOTS['van'], tbl + '.param'))
FL, _ = pf.fields_of(os.path.join(pf.PD, 'Defs', pdname + '.xml'))
bf = pf.bitfield_map(FL)
whole = {n.split(':')[0].split('[')[0]: (o, t) for o, t, n, d in FL}
o, t = whole[field]
bytes_ = [struct.unpack_from('<' + pf.TYPE_FMT[t], p['b'], p['datastart'] + i * p['rowsize'] + o)[0]
          for i in range(p['rowcount'])]
bits = pf.read_bitfield(p, bf[field])
print('%s.%s  位域=%s  类型=%s 偏移=%d' % (tbl, field, bf[field], t, o))
print('  按整字节非零: %d/%d' % (sum(1 for x in bytes_ if x), len(bytes_)))
print('  按位读取置位: %d/%d' % (sum(bits), len(bits)))
```

### D. 我在复核中发现的 6 处口径问题（诚实记录，也是你的面试素材）
