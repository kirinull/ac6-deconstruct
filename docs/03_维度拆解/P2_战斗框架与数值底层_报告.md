## 0. 结论先行（TL;DR）

1. **AC6 的战斗不是"伤害竞赛"，而是"两条正交血条 + 一个爆发窗口"的博弈**：AP 是慢变量，姿态（ACS 负荷）是快变量；把姿态打满换来一个 1~2 秒的窗口，窗口内用"直击补正"把伤害兑现。ACS 是整份战斗数值的**主干**，其余系统（EN、弹药、热量、武器互斥）都是围绕它做节奏限制的。**(B)**
2. **减伤既不是减法也不是（饱和度）乘法，而是"以 1000 为中性点的线性系数乘法"**：`最终伤害 ≈ 攻击力 × (2 − 防御值/1000) × 属性倍率 × 各种补正`。防御 1000 → ×1.0；1200 → ×0.8；800 → ×1.2。**(B，两处独立来源一致)**
3. **"姿态稳定"是阈值、"姿态回复"是衰减速度、"硬直持续时间"是第三个量**——三者常被混为一谈，但游戏里分开显示、来源也不同（稳定/回复来自框架部件与总重量，硬直时长更像系统常量）。**(A/B)**
4. **直击补正（Direct Hit Adjustment）是武器属性，单位为百分数**（装配界面上每把武器一栏，除以 100 即为倍率）。它**与防御项以"加法"方式耦合**的说法来自社区，但社区给出的样例数字内部有约 8% 的不一致 → 见第 4 节的 D 级条目。**(B/D)**
5. **三属性（动能/能量/爆炸）不是"物理 vs 魔法"的二分升级版，而是"装配取舍维度"**：它把"减伤"从一条轴拆成三条互相独立的轴，让同一台机体在不同敌人面前的短板不同。**(B)**
6. **能量武器射击直接从 EN 池扣能量**，和推进器（QB/突击推进）抢同一个池 → AC6 把老系列的"热量"概念**折叠进了 EN**：一个池、两种消费（机动 / 火力），这是最优雅的一处资源合并设计。**(B)**
7. **QB（快速推进）没有无敌帧**。AC6 的闪避是"空间闪避"而不是"时间无敌"，防御靠"位移 + 冷却管理"，不靠 i-frame。**(B，多来源一致)**
8. **本地数据侧可证实的"系统存在性"清单**（24 张与战斗直接相关的表，行数/行宽全部实测，见 1.1）：`EquipParamWeapon`(284×1556B)、`AtkParam_Pc`(712×1040B)、`AtkParam_Npc`(1748×1040B)、`AttackActionParam_PC`(418×100B)、`BehaviorParam_PC`(722×208B)、`Bullet`(568×888B)、`BulletShotgunParam_PC`(81×444B)、`BladeHomingParam`(10×64B)、`BladeHomingAngSpeedParam`(177×64B)、`BladeHomingAutoCancelEnableParam`(38×60B)、`KnockBackParam`(4×80B)、`ENAutoRecoveryControlParam`(2×160B)、`BoostParam`(2×128B)、`ShieldParam_Pc`(2×96B)、`PartsBreakParam`(1×80B)、`DamageLevelConvParam`(132×256B)、`DamageLevelConvThresholdParam`(57×208B)、`CalcCorrectGraph`(169×80B)、`CoolTimeParam`(40×32B)、`ThrustersParam_PC`(103×700B)、`EquipParamProtector`(121×900B)、`EquipParamGenerator`(24×340B)、`EquipParamBooster`(23×384B)、`EquipParamFcs`(19×208B)。**(实测)**
9. **⚠️ 表名同样不可信**：名为 `ShootReboundParam`（跳弹/反弹）的表，其载荷实测是骨骼名字符串（`R_ClavicleLink_Start` / `L_Clavicle` …）。因此**"跳弹"这条结论不能靠这张表验证**。这是本报告最重要的一条方法论警告。**(实测)**
10. **本机没有 AC6 专用 paramdef**，所以**列的语义一律 D 级**；但**列的数值是可信的**（数值可实测、语义只能推断）。报告里所有"槽 N = 某某"的说法都标了 D。**(实测)**
11. **TTK 与机制链长度必须匹配**：AC6 的一次完整"积累→硬直→爆发"循环约数秒，所以单场 AC 对战 TTK 在 10 秒量级；把 TTK 缩短 10 倍，ACS 系统会直接失效（详见第 11 节分析三问）。**(C)**
12. 对 TA 的落点：这套循环在 UE5 里可以完全用 **DataTable + CurveFloat + 一个固定顺序的伤害管线** 实现，核心工作量不在数学，而在**"管线顺序冻结 + 参数全部数据化 + 每次命中可分解输出"**这三件事上（详见第 12 节）。**(C)**

### 1.2 列的语义为什么一律 D 级

本机 `modengine2` 自带 `paramdef.paramdefbnd.dcx`（66119 字节）是**艾尔登法环系旧定义**，对 AC6 专有表基本只覆盖前一小段（例：它的 `LOCK_CAM_PARAM_ST` 只覆盖 100 字节，而 AC6 实际行宽 400 字节）。因此：

| 对象 | 可信度 | 说明 |
|---|---|---|
| 表是否存在、行数、行宽、类型名字符串 | **实测（A/B）** | 由文件头与行数据偏移直接得出，可复现 |
| 每列的数值统计（min/max/取值集合） | **实测（B）** | 数值可信 |
| 每列的**含义** | **D** | 必须等 AC6 专用 paramdex（Smithbox / Witchy）才能定论 |
| 表名暗示的作用 | **仅供参考** | 已被 `ShootReboundParam` 反例证伪 |

## 2. 战斗核心循环（0.2s → 10s）

### 2.1 文字流程图（括号内为该步的典型耗时量级，C 级估计）

```
[索敌/锁定]  0.2 ~ 1.5s   FCS 锁定 → 目标追踪（手臂 Firearm Specialization 参与）
      ↓
[决定姿态]   0.3 ~ 1.0s   接近（Assault Boost / 普通推进）或拉开（逆向 QB、掩体）
      ↓                    ← EN 开始被抽走
[输出窗口]   0.3 ~ 3.0s   开火：单发/连射/蓄力；每次命中同时结算 ①AP 伤害 ②姿态冲击
      ↓                    ← 弹药↓ 视线后坐↑ 热量/EN↓
[资源见底]   0.5 ~ 3.0s   EN 空 → 无法 QB / 能量武器打不出；弹匣空 → 强制装填
      ↓
[换弹 / 回能] 0.8 ~ 3.0s  装填时间（CartridgeBehaviorParam）；着地后 EN Recharge Delay 结束才开始回
      ↓
[姿态积累完成] 贯穿全程   累计冲击 ≥ 姿态稳定阈值 → ACS 过载
      ↓
[硬直窗口]   ~1 ~ 2s      敌方失控：不能推进/不能开火/不能闪；我方获得"直击补正"加成
      ↓
[爆发]       0.5 ~ 2.0s   蓄力重击 / 近战（Blade Homing 吸附）/ 高冲击武器 / 全弹发射
      ↓
[撤离/重置]  1.0 ~ 4.0s   QB 脱离、拉开距离、等自家 EN 与姿态回复，回到"决定姿态"
```

### 2.2 三层时间尺度

| 时间尺度 | 玩家在做什么 | 对应的数值层 | 数据侧证据 |
|---|---|---|---|
| **0.2 ~ 0.5s**（帧级） | 单次开火、单次 QB、单次命中判定 | 动作前摇/后摇、命中判定、后坐 | `AttackActionParam_PC`（418 行 × 100B）、`BehaviorParam_PC`（722 行 × 208B）**(实测存在)** |
| **1 ~ 3s**（决策级） | 换弹、回能、攒姿态、判断要不要 all-in | 装填、EN 回复延迟、姿态衰减 | `CartridgeBehaviorParam`(78×72B)、`ENAutoRecoveryControlParam`(2×160B)、`BoostParam`(2×128B) **(实测存在)** |
| **5 ~ 20s**（战斗级） | 赢得或输掉一次交战（TTK） | AP、总弹药、四槽冷却、Boss 阶段 | `EquipParamWeapon`(284 行)、`NpcParam`(1232×1920B)、`NpcThinkParam`(1178 行) **(实测存在)** |

**设计意图**：三层尺度必须**相互嵌套**——帧级动作决定 1~3s 的资源收支，1~3s 的收支决定 5~20s 的胜负。任何一层缺失，游戏就会退化成"纯 FPS"或"纯配装"。

## 3. ★ 姿态/硬直（ACS）系统：全报告最重要的一节

### 3.1 三个必须分开的量

| 量 | 游戏内名称 | 作用 | 来源/归谁调 | 等级 |
|---|---|---|---|---|
| **阈值** | 姿态稳定性能（Attitude Stability） | ACS 能承受的最大负荷；累计冲击 ≥ 它 → 过载硬直 | 头/核心/手臂/腿 四部件求和，受总重量与 OS 改造影响 | **A/B**（装配界面可直接读到；Fextralife 定义："The maximum load the ACS (Attitude Control System) can support"） |
| **衰减速度** | 姿态回复性能（Attitude Recovery） | **停止受击后**姿态条的下降速度；越轻越好 | 框架部件 + 总重量（"Lighter overall weight increases this value, leading to faster recovery from residual impact"） | **A/B** |
| **窗口长度** | 硬直持续时间（Stagger Duration） | ACS 过载后失控的时长 | 不是装配数值，更像系统常量/按敌人类型设定 | **D**（我没有找到可信的秒数；社区只有"大约一秒"这类模糊说法） |

**这三者分离是设计的关键**：如果"回复速度"同时决定"硬直时长"，那就只剩一个维度，玩家只会在"更硬"和"更快"之间二选一；拆成三个量后，重甲（高阈值 + 低回复）与轻甲（低阈值 + 高回复）是**两种不同的风险曲线**，而不是同一曲线的两个点。

### 3.2 状态机（机制层，四段式）

**① 设计意图**：把"输出"从"谁 DPS 高"改成"谁能在正确的时间点兑现爆发"；给低伤害但高冲击的武器（霰弹、爆炸系）一个不可替代的位置。

**② 实现手段（可观察到的）**：
- 每次命中结算两条独立通道：AP 伤害（走防御公式）与**冲击累积**（走阈值比较）。装配界面对每把武器显示两栏——**冲击力（Impact）** 与 **累计冲击（Accumulative Impact）**，这是一条 **A 级**的强证据：伤害被显式拆成"即时"和"累积"两种。
- 累积器 `IA += Impact`；当 `IA ≥ AttitudeStability` 时进入 Stagger 状态；Stagger 期间目标的输入（推进/开火/闪避）被剥夺。
- 非 Stagger 状态下，若距上次受击超过一段"宽限期"，`IA` 按姿态回复速率衰减（形状未知，**C/D**）。
- 姿态稳定受 OS 改造影响（社区讨论中提到 OS 升级会加"总姿态值"）**(C)**。

**③ 玩家体验/结果**：战斗出现**两个节拍器**——枪械的连射节奏，和"姿态条快满了"的节奏。玩家的决策从"要不要开火"变成"现在是不是爆发时机"。连续小口径命中的价值上升（累计冲击），单发大口径的价值也上升（瞬时冲击 + 直击爆发）。

**④ 可复用结论**：**"状态条 = 第二血条"**。只要给敌人加一条"会自我衰减、被打满就进入易伤状态"的条，就能把线性 DPS 竞赛变成有节奏的攻防。这条设计比"加血量"便宜得多，也比"加无敌帧"更能制造技巧表达。

### 3.3 直击补正（Direct Hit Adjustment）

- **A/B 级**：装配界面上每把武器有"直击补正"一栏，单位是百分比，**除以 100 即为倍率**（社区："The value is divided by 100 resulting in a percentage"）。
- **它与防御项如何耦合（D 级）**：社区的说法是 "Direct Hits interact with defenses in an **additive** way"，并给出一组样例：Stun Needle Launcher 裸攻击力 1088，对训练机（动能防御 1227）造成 842；触发直击时造成 2022。我按 `1088 × (2 − 1.227) = 841.0` **复算成功**（与 842 吻合，四舍五入），说明**非直击路径的公式是可靠的**；但直击路径按其自述的表达式应为 2201 而实测 2022（差约 8%），作者自己怀疑存在一个"硬度（hardness）"机制在削减直击加成。→ **我不复述那个表达式，只保留结论："直击补正作用在攻击力侧、与防御项以加法方式耦合"是社区假说，精确形式未定论（D）。**
- **验证方法（可执行）**：训练场固定一把武器与一个目标，分别记录 ①非硬直命中伤害 ②硬直窗口内命中伤害 ③同一武器对不同防御值目标的两组数据，然后用 4 个未知量（攻击力、防御系数、直击倍率、修正常数）做最小二乘拟合。

### 3.4 为什么"把敌人打晃"比"直接堆伤害"更好玩？它替代了什么？

**它替代了"纯 DPS 竞赛"这一传统做法。** 纯 DPS 竞赛的问题：所有武器被压缩成一个标量（DPS），装配空间退化成一维排序；玩家的技巧只剩"准不准"。

ACS 用**一条会衰减的第二血条**同时买到三件事：

1. **让"命中时机"变成独立技巧**：命中率（准）与命中窗口（稳）分离，两个技能各自都能提升。
2. **把武器差异从一维变二维**：伤害 × 冲击力构成平面，于是"低伤高冲"（霰弹、爆炸）与"高伤低冲"（激光狙击）都有位置。社区观察也印证这一分工："Explosive has the most stagger damage. Kinetic generally has better stagger and EN often has better base damage"**(B)**。
3. **给了爆发一个合法的"授权"**：直击补正让窗口内的伤害显著高于平时，玩家的目标从"持续输出"变成"攒窗口 + 兑现窗口"，这就是 AC6 的战斗语法。

它同时也**没有**采用另外两种常见替代方案：①**处决/背刺式的一次性大伤害**（离散、不可连续博弈，且对远程武器不公平）；②**无敌帧/弹反**（把防御做成"时间精确"而非"空间精确"，与机甲题材的"机动"卖点冲突）。AC6 选了"资源积累 + 空间机动"，这与它整机的手感定位一致（见第 8 节：QB 无无敌帧）。

## 4. 三大伤害类型与三种抗性

### 4.1 是减法还是乘法？——**都不是，是"线性系数乘法"**

社区的**实测公式（B 级，Reg 1.09.1）**：

```
最终伤害 ≈ 武器攻击力 × (2 − 防御值 / 1000) × 属性耐性 × 各种补正
```

另一处独立表述（B 级）："**防御值是以 1000 为基准的千分偏差**"——训练机（动能防御 1227）承受动能伤害时约 **减少 22.7%**。两者互相验证：`2 − 1.227 = 0.773`，正好是 −22.7%。

| 防御值 | 倍率 `2 − D/1000` | 相对 1000 的变化 |
|---:|---:|---:|
| 800 | 1.20 | +20% 承伤 |
| 1000 | 1.00 | 基准 |
| 1100 | 0.90 | −10% |
| 1227 | 0.773 | −22.7%（训练机实测） |
| 1300 | 0.70 | −30% |
| 1500 | 0.50 | −50% |

**判定方法（给读者的可执行清单）**——要自己确认"减法 / 乘法 / 线性系数"哪一种：

1. 固定一把武器、一个目标，只改目标防御值，记录 5 组以上 `(D, damage)`。
2. 若 `damage` 对 `D` 是**直线**且斜率为 `−攻击力/1000`，截距在 `D=1000` 处等于攻击力 → **线性系数乘法**（AC6 属于此类）。
3. 若是 `damage = 攻击力 − k·D`（斜率为 `−k` 且与攻击力无关）→ **减法**。
4. 若是 `damage = 攻击力 × (1 − D/(D+K))` 这类曲线（斜率随 D 变小）→ **饱和乘法**。
5. 注意清除 OS 改造（伤害加成在防御计算**之前**生效，防御类改造在**之后**生效——社区说法，B 级），并在训练场用同一台目标机测。

**为什么这个形式很聪明（设计视角）**：`(2 − D/1000)` 是**线性且无上限塌缩**的——不会像 `1 − D/(D+K)` 那样永远吃不满收益，也不会像纯减法那样在低攻击力武器上出现"打不动"的硬墙。它让"每 100 点防御 = 10% 减伤"成为玩家可以心算的规则，直接服务于装配决策。

### 4.2 属性克制在装配层面的实际影响

- **A/B 级**：训练机（Melander 部件）三抗为 动能 1227 / 能量 1105 / 爆炸 1194，对应减伤 −22.7% / −10.5% / −19.4%。**同一台机体在不同属性面前的承伤差可达约 12 个百分点**——这就是"属性克制"的实际量级。
- **B 级补充**：能量武器还有一条**发电机侧的系数**：例如 150 规格的发电机把能量武器伤害提到约 125%（约每点 0.5%），且充能速度提升到 150%。也就是说**能量武器的伤害同时受"目标能量抗性"和"自家发电机"两个变量影响**，而动能/爆炸没有这条通道。这让"能量流"成为一种独立的装配流派。
- **B 级**：有效射程与跳弹也受防御影响（"Higher defense values also impact effective range shortening (Ricochets)"），即高防御目标会让你的武器**更早开始跳弹**——防御属性实际上同时买了"减伤"和"压缩对方有效射程"两件事。

### 4.3 为什么是三属性，而不是"物理 / 魔法"二分？

| 维度 | 二分（物理/魔法） | AC6 的三分（动能/能量/爆炸） |
|---|---|---|
| 装配取舍 | 只有一条抗性轴，最优解趋于"堆短板" | 三条独立轴，部件之间必然产生**取舍三角**，没有全局最优 |
| 武器身份 | 武器只差数值 | 属性 = 武器家族标签（实弹 / 激光·等离子·脉冲 / 火箭·榴弹·导弹·加农），玩家看敌人装配即可预判 |
| 与姿态系统的耦合 | 无关 | 三属性在"冲击力 vs 伤害"上有系统性偏移（爆炸系冲击更高），属性选择同时是姿态策略选择 **(B)** |
| 敌人设计 | 弱点只有"怕魔法" | BOSS/AC 可在三种抗性上做不对称，逼玩家改装配而不是改手法 |

**一句话**：三分不是"两种元素不够用"，而是**为了给装配界面买到第三条正交的取舍轴**。二分会退化成"这套敌人抗物理 → 换魔法武器"的单一开关。

## 5. 四武器槽的职能分工与开火互斥

### 5.1 职能分工

| 槽位 | 典型职能 | 与其它槽的关系 | 等级 |
|---|---|---|---|
| 右手 | 主武器：持续输出 / 主战手段 | 与左手共享"手臂负荷"，超载会掉目标追踪与后坐控制 | **A/B** |
| 左手 | 副武器：补盲（近战刀、霰弹、盾、副枪） | 可与右手"同时开火"或轮替，取决于武器动作 | **A（可观察）/C（机制）** |
| 右肩 | 重火力：导弹 / 加农 / 榴弹 | 多数需要**展开/架设动作**，占用上半身动作 | **A/C** |
| 左肩 | 功能位：护盾 / 干扰 / 导弹 / 垂直发射 | 同上 | **A/C** |

### 5.2 开火互斥表（**请严格区分知识与推断**）

| 组合 | 是否可同时 | 等级 |
|---|---|---|
| 右手 + 左手（同帧开火） | **可以**（存在双臂齐射） | **A**（游戏内可观察） |
| 手臂武器 + 肩部武器 | **受限**：肩部武器有独立动作（展开/后坐/架设），期间身体进入一段"动作锁定" | **A（现象）/ C（机制解释）** |
| 肩部武器 × 肩部武器 | 通常**不能**同帧齐射，需排队 | **A（现象）** |
| 近战武器（Blade） | 强制突进 + 吸附，期间手臂动作被占用 | **A（现象）** |
| 蓄力类武器 | 蓄力期间手臂动作被占用 | **A（现象）** |

**数据侧对应的实现层**（实测存在这些表，说明互斥是"数据驱动 + 动作状态机"而非硬编码）：

- `AttackActionParam_PC`：**418 行 × 100 字节（25 个槽）**——一行 = 一个攻击动作，25 个槽足以容纳前摇/后摇/取消窗口/位移曲线引用等字段。
- `BehaviorParam_PC`：**722 行 × 208 字节（52 个槽）**——一行 = 一个"行为"（动作/状态），比攻击动作更粗粒度。
- `AttackActionParam_NPC` / `BehaviorParam`（3069 行）是敌方侧的对应表，**说明玩家和敌人共用同一套动作/行为参数体系**（这是"敌人 AC 与玩家 AC 同构"这一设计在数据层的体现）。

**设计意图**：互斥不是为了"惩罚"，而是**制造动作成本**——四槽不是四个并联的 DPS 通道，而是一张**时间表**。玩家必须为"什么时候开哪一件"做排序，这正是"机甲操作感"的来源。若四槽完全并行，游戏会退化成"四把枪的 DPS 相加"。

### 6.1 资源流向图


| **热/过热** | —— | —— | —— | `CoolTimeParam`(40×32B，id 从 101 起，前 6 槽实测为 `900/600/600/450/300/200` 的阶梯常量) — **实测存在，语义未知** | **D** |

| **AP** | 装配固定 | 被命中 | **不可回复** | `EquipParamProtector`(121×900B)、`NpcParam`(1232×1920B) | **A** |

### 6.3 关于"热/过热"这一条，我必须说实话（重要）

任务书要求把"热量/过热"列为五种资源之一。**我无法从本地数据里确认 AC6 存在一条独立生效的"热量条"**：`CoolTimeParam`（40 行 × 32 字节，8 槽）确实存在，但它的取值是 `900/600/450/300/200` 这类阶梯常量，语义完全未知（D 级）。

我**能**确认（B 级，两处独立来源）的是：**所有远程能量武器都有"每发子弹成本"，射击从 EN 池扣能量**（"all of ranged EN weapons have bullet costs, use more energy per shot"；"shooting energy weapons cost energy per shot, if depleted you couldn't use any of them"）。

**我的推断（C 级）**：AC6 把老系列（AC4/FA 等）的"热量"概念**折叠进了 EN**——推进与能量武器共用同一个池，于是"机动性"与"能量火力"互相挤占。这是一个**资源合并**的设计选择：少一条 UI 条、少一套教程，但把"我该不该现在开这一枪"变成了一个真实的取舍。

**验证方法**：①游戏内观察是否存在独立热量表/过热提示；②测"打空 EN 后能否立刻 QB / 打空 EN 后能否继续发射能量武器"；③用 Smithbox 查 `CoolTimeParam` 与 `ThrustersParam_PC` 的列名。

### 6.4 五种资源的相互关系（一句话总结每种资源"在约束什么"）

- **EN** 约束**机动预算**（并且顺手约束了能量火力）；
- **弹药** 约束**持续时间**（把无限输出变成有限输出，逼你换弹走位）；
- **AP** 约束**容错次数**（不可恢复，唯一真死线）；
- **姿态** 约束**进攻节奏**（会自我衰减，所以"持续压制"和"一波爆发"是两种策略）；
- **热（如存在）** 约束**连射节奏**（D 级，待验证）。

> **TA 视角的落点**：这五条本质上就是**五个标量 + 五条曲线**。把它们全部放进 DataAsset / DataTable，配上 GameplayEffect（或自建 ResourceComponent）就能跑起来；难点不在实现，而在**让策划能看见"谁扣了谁"**（需要 HUD 与调试输出，见第 12 节）。

| **散射** | 霰弹/机枪有散布；**霰弹的散射被单独做成一张表**（81 行，行宽 444B，是普通子弹表的一半） | **A/C** | `BulletShotgunParam_PC`（**实测存在**） |
| **AoE** | 爆炸系有爆炸半径与衰减 | **A（现象）** | 未在本机确认具体表/列（**D**） |
| **跳弹（Ricochet）** | 与**射角**和**有效射程**相关；社区指出高防御目标会**缩短你的有效射程**，只有理想射程内才保证不跳弹 | **B** | ⚠️ `ShootReboundParam` 实测载荷是骨骼名，**不能用来验证跳弹**（见 1.1(f)） |

**近战吸附的机制描述（B/C 级）**：近战武器在攻击时会获得一个**朝向修正**（在允许的角度范围内把机体转向目标），角度上限与角速度分表控制，并且有一张专门的表定义"什么情况下自动取消吸附"（例如目标位移过大 / 出招被打断）。这解释了 AC6 近战的手感：**近战不是靠判定框变宽，而是靠"机体被允许转向"**——这一点对 TA 极有价值，因为它的实现是"动画/物理层"，不是"碰撞层"。

**设计结论（可复用）**：AC6 用"**空间闪避 + 冷却**"而不是"**时间无敌**"来做防御，是因为机甲题材的核心幻想是**机动**，而不是"读帧弹反"。代价是：玩家被弹幕覆盖时没有"保命按钮"，因此**敌人弹幕必须可读、可绕**（这直接决定了第 9 节敌人三段式结构必须做得很清楚）。

## 9. 敌方战斗结构：预警 → 出招 → 收招

### 9.1 三段式（玩家视角）

```
[预警]  0.3 ~ 1.2s   音效 + 发光/蓄力 VFX + 身体预备动作（可通过 AiSoundParam / 动作表配置）
    ↓                 ← 让玩家有"可以闪了"的明确信号
[出招]  0.2 ~ 1.5s   攻击判定生效（有些带位移/追踪）
    ↓
[收招]  0.5 ~ 2.0s   动作后摇 = 玩家的惩罚窗口；重攻击后摇更长
```

**数据侧证据（实测存在）**：`AiSoundParam`(34 行) 管 AI 音效（预警音）、`AttackActionParam_NPC`+`BehaviorParam`(3069 行) 管敌方动作、`NpcThinkParam`(1178 行) 管思考/决策、`EnemyCommonParam`(1×256B) 管敌人通用常量。**注意 `EnemyCommonParam` 只有 1 行** → 敌人通用规则是全局单例，差异靠各表行区分。

### 9.2 这套结构在攻防节奏上的作用（四段式）

- **意图**：让"防御"成为一次**信息判断**（读预警 → 选方向 → 花 EN），而不是反应测试。
- **手段**：把每个敌人攻击拆成"可观察信号段 / 判定段 / 可惩罚段"三段，且**每段的时长写进数据表**（不是硬编码在动画里），所以可以整体调参。
- **体验**：玩家形成"看见光就侧闪 → 等收招 → 打两枪 → 攒姿态"的循环。因为 QB 没有无敌帧，玩家必须**提前离开判定区域**，所以预警段必须够长、够清晰。
- **可复用结论**：**"没有无敌帧的游戏，必须给足预警时间"**——预警时长与防御手段的容错度是一对必须联调的参数（这也解释了为什么 AC6 的 BOSS 大招都有夸张的蓄力演出）。

## 10. BOSS 战的阶段化与"读招—惩罚"循环

- **阶段化（A 级现象 / C 级机制）**：Boss 通常按血量阈值或部位破坏切换阶段，切阶段时重置姿态条与部分动作集（社区也普遍报告"Boss 开场姿态条状态异常"这类现象）。数据侧对应 `NpcThinkParam`（1178 行，决策切换）+ `BehaviorParam`（3069 行，动作集）+ 可能的 `SpEffectParam`（4120 行，状态效果）。
- **读招—惩罚循环**：`读预警 → 闪避（花 EN） → 惩罚收招（攒姿态） → 姿态满 → 爆发（直击补正） → 阶段切换`。注意这个循环里**每一次惩罚都在为下一次爆发存款**，所以 Boss 战的时间结构是"越打越快"（玩家越熟练，姿态积累越快，爆发越频繁），而不是"血条匀速下降"。
- **设计意图**：把"难度"从"血量/伤害数字"转移到"招式可读性与惩罚窗口大小"。这样**同一套数值可以支撑很大的难度区间**（玩家熟练度完全体现在姿态积累效率上）。
- **D 级说明**：我**没有**验证 AC6 的 Boss 是否存在"阶段切换时姿态条重置"。验证方法：在训练场/竞技场用固定武器，在 Boss 血量跨过阈值前后记录姿态累积所需命中数。

## 11. 分析三问

### 问 1：删掉 ACS 硬直系统会怎样？

- **玩家体验变化**：战斗退化为"AP 消耗速度竞赛"。因为实弹/能量/爆炸三类武器的差异主要体现在"伤害 vs 冲击"的配比上，删掉冲击通道后，所有武器被投影到单一 DPS 轴上 → **装配界面 90% 的信息失去意义**，"冲击力/累计冲击/姿态稳定/姿态回复"四个数值栏直接作废。
- **次级后果**：低伤高冲武器（霰弹、爆炸）变成纯劣势；重甲（高姿态稳定）的卖点消失，只剩 AP 与防御；战斗节奏从"两拍"变成"一拍"，玩家的技巧表达只剩准度与走位。
- **结论**：ACS 不是"锦上添花的第二血条"，它是**武器与装甲多样性的承重墙**。

### 问 2：删掉三属性克制会怎样？

- **装配维度塌缩**：从 3 条独立抗性轴降到 1 条 → 部件选择从"三角取舍"退化为"总防御值排序"，最优解变成唯一的（堆最高总防御 + 最高 AP）。
- **武器维度塌缩**：能量武器的"发电机系数"通道失去对手（没有能量抗性可以对抗它），能量流变成无脑最优或完全无用（取决于数值）。
- **敌人设计手段减少**：Boss 的"抗性不对称"这一设计手法只能用"血量/减伤百分比"代替，而后者对玩家是不可见的 → 玩家会感到"这 BOSS 就是肉"，而不是"我该换武器"。
- **结论**：三属性买到的是**装配空间的维度**，不是"属性相克的小乐趣"。

### 问 3：TTK 缩短 10 倍会怎样？

设当前一次 AC 对战的 TTK 在 10 秒量级（C 级估计），缩短 10 倍后变成 1 秒量级：

1. **ACS 直接失效**：姿态条需要"多次命中 + 阈值比较"才能打满；1 秒内打不出足够的累积冲击。整个第 3 节的循环（积累 → 窗口 → 爆发）跑不完一个周期。
2. **EN/弹药管理退化**：QB 与换弹的时间成本相对于 TTK 变得不可接受 → 玩家会取消所有非必要动作，游戏退化成"先手即胜"。
3. **所有"延迟收益"的设计失效**：换弹、回能延迟、姿态衰减、蓄力攻击全部变成负收益。
4. **设计空间边界（这是本题真正要的答案）**：**TTK 必须 ≥ 机制链长度 × 单环耗时**。AC6 的机制链大约是"3~4 环"（攒姿态 / 兑现爆发 / 回资源 / 再进入），单环 2~4 秒 → TTK 下限在 8~15 秒量级。**换句话说，机制越多，TTK 越不能短；这不是手感问题，是数学约束。**

## 12. TA 转化：UE5 最小战斗原型（可直接照做）

### 12.1 目标与范围

实现"**姿态积累 → 硬直 → 直接命中加成**"这一条最小闭环，其余（EN、弹药、AI）先用占位数据。整个原型只需要 **4 个 DataTable + 1 个 CurveFloat + 1 个组件**。

### 12.2 数据结构（DataTable 设计）

### 12.3 伤害与姿态管线（**顺序必须冻结**）

```cpp
// 一次命中的结算（伪代码，顺序即设计）
float ComputeDamage(const FWeaponStats& W, const FFrameStats& T, bool bStaggered, float HitAngleDeg)
{
    // ① 攻击力侧修正（OS/发电机等，在防御之前生效 —— 社区说法）
    float Atk = W.AttackPower * Attacker.OffenseMultiplier;

    // ② 直击补正：只在硬直窗口内生效
    if (bStaggered) Atk *= (W.DirectHitAdj / 100.f);

    // ③ 防御：线性系数（AC6 实测形式）
    float DefFactor = 2.f - T.Defense[W.DamageType] / 1000.f;   // clamp 到 [0, 2]

    // ④ 属性倍率（预留：发电机/材质等）
    float AttrFactor = 1.f;

    // ⑤ 跳弹：按入射角与有效射程判定
    float Ricochet = bRicochet ? RicochetDamageScale : 1.f;     // 具体规则待游戏内实测

    // ⑥ 防御类修正（在防御计算之后生效 —— 社区说法）
    float Final = Atk * DefFactor * AttrFactor * Ricochet * Defender.DefenseMultiplier;
    return FMath::FloorToFloat(Final);   // 社区观察到伤害是整数（四舍五入/截断未定论）
}

// 姿态累积（与伤害完全独立的一条通道）
void ApplyImpact(AActor* Target, float Impact)
{
    Stagger->IA += Impact * MaterialImpactMul;
    if (Stagger->IA >= Frame.AttitudeStability) EnterStagger();  // 阈值比较
}
```

**衰减（放在 Tick 或用 Timer）**：

```cpp
if (!bStaggered && TimeSinceLastHit > Profile.DecayDelay)
{
    // 把"姿态回复性能"做成曲线的时间缩放：值越大，衰减越快
    float Speed = BaseDecayRate * (Frame.AttitudeRecovery / 100.f);
    Stagger->IA = FMath::Max(0.f, Stagger->IA - Speed * Profile.DecayCurve->GetFloatValue(NormalizedTime) * Dt);
}
```

### 12.4 开火互斥（用 GameplayTag + 能力系统实现）

- 每个攻击动作给持有者打一个 `State.Fire.Arms` / `State.Fire.Back` / `State.Fire.Melee` 标签；
- 开火前检查：若自身已带互斥标签 → 拒绝（或排队）；
- 肩部武器额外使用一个 `AnimMontage` 展开段，展开期间上 `State.Deploy` 标签（这就是"肩部武器与手臂武器冲突"的可实现形式）。
- **好处**：互斥规则变成策划可读的标签矩阵（也是 AC6 用 `AttackActionParam_PC` + `BehaviorParam_PC` 分两层表达同一件事的思路）。

### 12.5 让策划可调的关键三件事

1. **管线顺序冻结**：把上面的 ①~⑥ 写成固定顺序的函数，每步留一个 `Modifier` 插槽；**顺序一旦变动，所有已调好的数值全部作废**——这是最容易踩的坑。
2. **全部数值进 DataTable / DataAsset，且必须有"来源可追溯"**：每条数据标注是移植自 AC6 还是原型自定。
3. **命中分解输出**：每次命中用 `UE_LOG` 或 GameplayDebugger 打印
   `Atk=.. DefFactor=.. DirectHit=.. Final=.. IA=../ threshold=..`
   ——**没有这一行日志，数值调试会变成玄学**。同理，HUD 上必须同时显示 AP 条与姿态条（含阈值刻度与衰减方向）。

### 12.6 性能与工程注意（TA 视角）

- 弹丸用 **对象池 + `UProjectileMovementComponent`**，不要每帧 `LineTrace` 求 AC；
- 命中判定分两层：`hitscan` 武器走单次 `LineTrace`（带 `RicochetAngleDeg` 判定）；实体弹丸走"每帧小步长 sweep"，避免穿透薄壳；
- 姿态衰减用 **Timer 而不是 Tick**（衰减只在受击后发生）；
- 数值全部 `float`（不要 `double`），且所有配置项在 `DataTable` 里**不要写死在 C++ 默认值**里——否则策划改不动。
