# 《装甲核心6：境界天火》剧情与叙事结构 拆解报告

> 读者：大四学生，目标技术美术（TA），从策划岗入门。
> 本报告的纪律：**不复述剧情梗概**。每一条都回答「这个叙事效果是用什么载体、什么触发条件实现的」。
> 证据分级：A = 游戏内可直接观察 / 官方公开资料；B = 社区实测·Wiki·数据挖掘；C = 基于同类游戏的合理推断；D = 不确定（附验证方法）。
> 本机实测的命令与原始输出集中在 §11，正文凡标「实测」处均可回溯到该节。

## 0. 结论先行（TL;DR）

| # | 结论 | 等级 |
|---|---|---|
| 1 | AC6 的叙事预算几乎全部押在**一个通道**上：实测英文「会話」文本池 5965 条 / 248,181 个 UTF-16 码元，而邮件表只有 46 行、档案正文只有 51 条。台词池是第二大叙事通道（教学文本）的 6.6 倍。 | B（计数实测） |
| 2 | 这个被押注的通道是**可控性最低**的一条——它只能在战斗中、由 AI 决定何时开口。原因不是"更沉浸"，而是它在成本结构上有唯一优势：**玩家已经在操作，注意力是免费的**；而配音成本与文字成本在此通道上是同一个数量级。 | C（推断） |
| 3 | 沉默无脸主角换来三件工程学红利：装配系统无需承担角色成长叙事、分支不需要表演主角反应、本地化成本被压缩到只剩台词表。代价是**角色弧光被外包给无线电里的配角**。 | C |
| 4 | 代价补偿机制是一套「代你说话」的三角色配置（雇主 / 异质他者 / 镜像对手），且主角的**人格表达被转移到机体外观系统**（涂装、徽章、贴花相关表在数据里实际存在，实测）。 | B（表存在）/ C（机制解读） |
| 5 | 三结局的分歧不是「一条线走到底」，而是**决策任务对**：同一时刻在 Sortie 菜单里挂出两份带专用图标的简报，两份都可以进去听、可无成本退出，确认执行一份后另一份从菜单消失。 | B（IGN / Fextralife） |
| 6 | 前两个结局（The Fires of Raven / Liberator of Rubicon）在第五章同一分歧点自由二选一，NG 即可；第三个（Alea Iacta Est）**独占 NG++**，且要求一整套指定决策路径 + 通关竞技场后开启专属任务链 MIA → Regain Control of the Xylem → Coral Release。 | B |
| 7 | 分支与玩法的耦合点不只是剧情：**每条分支给一套专属机体部件**（HAL 826 / ALBA / JAILBREAK）。这让"选边"从叙事判断变成**装配构筑判断**——这是把叙事决定接到了核心循环上。 | B |
| 8 | 碎片化与可达性的平衡点是分工：**世界史碎片化**（档案 51 条 + 场景拾取），**当下指令广播化**（战斗中通讯）。玩家永远确定"下一步打哪"，但不确定"这个世界到底怎么回事"。 | C |
| 9 | 所有「第 N 列 = 什么」的列语义在本机**只能推断**（本机 paramdef 是法环系旧定义），因此本报告只把**行数、行宽、ID 空间、跨表交集**当作结论，列语义一律 D。 | A（本机工具链事实） |
| 10 | 叙事系统的技术本质是一个**「已完成任务集合 + 决策组已选项」的存档 + 由数据表反推任务可用性**的有限状态机；过场只是这个状态机的一个可选输出轨道。 | C |

## 1. 证据基础与可信度声明

### 1.1 我实际跑过的命令（原始输出见 §11）

- 表结构/行数/行宽：本机既有工具 tools/param_inspect.py（souls 扩展行格式 LONGDATA，走 didx 字段）
- 表 ID 全量、跨表 ID 交集、计数：自写 _p3/analyze.py
- 文本投放量：自写 _p3/fmg2.py（解析本机解包的 FMG 二进制，统计空终止串与 UTF-16 码元）
- mod 差异：对 van / mob / reibis 三份 regulation-bin 逐行字节比较

### 1.2 为什么列语义一律 D 级

本机 modengine2 自带 paramdef.paramdefbnd.dcx 是艾尔登法环系旧定义，AC6 专有表列名不可采信。
因此：
- **可以当结论的**：行数、行宽（字节）、行 ID 全量、ID 前缀分桶、跨表 ID 交集、UTF-16 码元计数。
- **不能当结论的**：任一列代表什么、哪一列是文本 id、哪一列是解锁条件。
后者必须用 AC6 专用 paramdex（Smithbox / DSMapStudio AC6 版）打开才能定论。

### 1.3 一条必须声明的口径

FMG 的「UTF-16 码元数」≈ 字符数（含空格与标点），**不等于**英文单词数，也不等于中文字数。
本报告用它做**通道之间的相对比较**，不对绝对值做任何叙事学解读。

## 2. 叙事载体清单：六条通道的密度 / 可控性 / 成本

### 2.1 通道总表（投放量全部来自本机实测，见 §11.3）

| 通道 | 载体（数据表 / 文件） | 实测投放量（英文） | 单条均长 | 接收时机可控性 | 单位内容成本 | 主要失效模式 |
|---|---|---|---|---|---|---|
| **任务简报** | MissionParam（111 行）+ ミッション名 67 条 / ミッション概要 67 条 / ミッション目標 67 条 / ミッション地点名 59 条 | 约 260 条串 / 约 12,800 码元 | 20–115 | **中**：只能在地图/Sortie 菜单看，可反复看，但必须切出战斗 | 低：纯 UI 文本，且无论如何都得写 | 玩家按「确认」跳过 |
| **战斗中通讯（comm）** | TalkParam（6013 行）+ 会話.fmg | **5965 条 / 248,181 码元** | 41.6 | **最低**：说了就说了，只有字幕/语音，不能回看（重打任务才重播） | 中：每条要配音 + 字幕 + 触发脚本；台词本身与纯文本同价 | 玩家在躲弹幕，字没看进去 |
| **过场动画** | CutsceneGparamTimeParam(4) / CutsceneGparamWeatherParam(1) / CutsceneMapIdParam(74) / CutsceneReplaceSfxParam(38) / SoundCutsceneParam(105) / GarageCutsceneParam(3) | 表条目数即「可调度的过场环境配置数」，**不是**过场数量 | — | 高：一次性、强制观看 | **最高**：动画、相机、灯光、动作、音频、分镜，按分钟计价 | 成本高导致数量少；跳过后信息永久丢失 |
| **场景拾取物 / 文档** | ArchiveParam（57 行）+ アーカイブ内容.fmg（51 条，均长 372） | 51 条 / 18,965 码元 | **371.9（全通道最长）** | **最高**：可随时重读、可暂停 | 中：长文本写作成本高，且**必须配一个可拾取/解锁的几何体** | 玩家不读 |
| **邮件系统** | MailParam（46 行） | 46 条（其中 20 条卡号段 + 26 条 9999xxxx 系统段） | — | 高：菜单里可反复读，但**要玩家主动打开** | 最低：纯 UI 文本，无配音无演出 | 送达率极低（玩家不点菜单） |
| **结局演出** | 无独立表；由最后一串任务 + 过场承担 | — | — | 100%（就在结尾，绕不开） | 高，但只买一次 | 无 |

**三条立刻可用的判断：**

- **投放量最大的通道，可控性最差**。5965 条台词里没有一条能被玩家「往回翻」。
- **均长最长的通道，投放条数最少**。档案正文平均 371.9 码元/条（是 comm 的 8.9 倍），但总共只有 51 条。这是一条**成本守恒曲线**：长文写作贵、还得给一个可拾取的载体，所以条数被压到极致。
- **任务简报是被低估的通道**。它本来就必须存在（玩家得知道去哪），加叙事的**边际成本接近零**。实测英文简报表共 260 条串 ≈ 12,800 码元，相当于台词池的 5.2%，但它是唯一「100% 送达」的一次性入口。

### 2.2 为什么 AC6 更依赖战斗中通讯（四段式）

**设计意图**：AC6 的核心循环是「接单 → 出击 → 交战 → 结算 → 改装」。叙事必须在**不打断这个循环**的前提下推进。任何要求玩家「停下机甲、读一段字」的载体，都在和循环抢时间。

**实现手段（可观察的）**：
1. 台词池被做成**唯一的大表**（TalkParam 6013 行 × 64 字节），所有阵营角色共用同一张表，用行 ID 的高位段区分说话人与场景（实测 ID 位数分布：9 位数 5993 条 / 8 位数 20 条；前两位分桶为 10:3305、11:436、20:426、30:417、93:176、70:164、91:162、40:155、60:123、80:111、21:100、94:96、99:80、52:48……）。**一条通道，多说话人**，管线只有一条。
2. 语言本地化按「文件 = 通道」切分。同一批文件在英文与中文目录下**字符串条目数几乎相同**（会話 5965 vs 5964；メニューテキスト 1721 vs 1720；アーカイブ内容 51 vs 51），说明表结构固定、只换文本——这是**流水线化**的证据。
3. 有专门的**音频过场替换表**（CutsceneReplaceSfxParam 38 行）与 **SoundCutsceneParam（105 行）**，说明「通讯/过场的声音」是独立可调度的资源层，不需要为了改一句台词去碰动画。

**玩家体验/结果**：叙事是「背景音」而不是「拦路的门」。代价是**信息吸收率不可控**——玩家在打 Boss 时把台词当白噪音，这是设计者主动接受的风险，而非疏忽。

**可复用结论**：把大叙事池放在「玩家本来就在做别的事」的时间轴上，是低成本高覆盖的投放策略；但它要求两件事：①一张**能承载全部说话人**的扁平表；②一套**不依赖玩家停下来**的字幕/语音 HUD。AC6 两者都有。

## 3. 沉默无脸主角：得到了什么，牺牲了什么

### 3.1 三件工程学红利

| 红利 | 具体表现 | 为什么只有沉默主角才能拿到 |
|---|---|---|
| **装配自由** | 玩家随时换全身部件、换武器、换腿部形态，外观剧变 | 一个「有脸、有身体」的主角一换装就要重做面部/体型叙事，沉默+机甲壳把角色身份锚定在**机体**而不是**人** |
| **代入成本为零** | 不需要为主角写动机、写成长、写台词分支 | 所有台词都由配角说，主角只需「在」 |
| **分支只需改数据** | 决策只体现在任务列表增减，不需要为主角的反应做表情/演出 | 若主角会说话，每个分支都要写他的反应并配音 |

### 3.2 被牺牲掉的东西

| 牺牲项 | 后果 | 是否被补偿 |
|---|---|---|
| **角色弧光** | 主角不能「改变」，只能「被改变」；全作的「成长」体现在机库与竞技场排名，不在人物 | 部分补偿：靠排名/评价系统把成长数值化（ArenaParam 42 行、MercenaryRankTable 表存在） |
| **情感表达** | 主角无法主动表达立场、愤怒、犹豫；所有情绪必须由别人替他说 | 补偿：见 3.3 |
| **关系主动性** | 主角无法发起对话，所有关系都是**被联系** | 补偿：邮件系统（46 条）是唯一单向的「别人找你」通道 |
| **结局的「人味」** | 结局的分量落在配角身上（你为谁而战），不在你身上 | 补偿：结局演出 + 专属部件归属 |

### 3.3 代价补偿机制：代你说话的三角色配置

沉默主角必须配置「替他说」的角色，且这些角色要在**结构上互斥**才能形成张力：

| 角色 | 说话位置 | 结构职责 | 把握程度 |
|---|---|---|---|
| **Handler Walter（管理人沃尔特）** | 通讯最常驻 | 雇主/权威：给任务、给理由、给道德框架 | 名字拼写 B（社区通用）；中文译名 D |
| **Ayre（艾尔）** | 第四章后渐增 | 异质他者：不是人，替玩家提问「你们人类……」 | B |
| **Rusty（拉斯提）** | 跨章节反复出现 | 镜像对手/理想化的自己：同一编号体系的另一条路 | B |
| **"Cinder" Carla（灰烬卡菈）** | 中期后 | 旧时代的遗民：把「伊比斯之火」的历史人格化 | B（绰号拼写来自 IGN/Fextralife） |
| **V.II Snail / V.III O'Keeffe 等 Vespers** | 中期后 | 体制的傲慢：把「企业秩序」人格化 | B（编号体系） |
| **ALLMIND（奥尔曼德）** | NG++ 专属 | 幕后势力：从菜单 AI 变成第三阵营 | B（IGN 明示 NG++ 独占） |

**一个关键的可验证观察（实测）**：主角的人格表达被**外移到了外观系统**。本机表清单里实际存在 PlayerColoringPresetParam、PlayerMaterialPresetParam、PlayerWeatheringTexPresetParam、PlayerCamouflagePattern、EmblemPieceSpec、PresetEmblemSpec、UnlockParam_EmblemPiece、UnlockParam_DecalImage 等表。
→ 「涂装 + 徽章 + 贴花」是这套叙事留给玩家的**唯一自由表达面**（表存在 = B；这一点的设计意图解读 = C）。这也解释了为什么解锁徽章/贴花/涂装被做进 UnlockParam_* 体系——它们和剧情解锁共用同一套解锁框架。

## 4. 信息分期揭露：骨架与节奏

### 4.1 为什么顺序是这样（核心机制）

AC6 的信息排序不是按「世界编年史」排的，而是按**玩家此刻的需求**排的：

1. **我该去哪、打谁** →（必须最先给）任务简报，100% 送达，零成本。
2. **正在打的是谁、他想要什么** →（战斗中给）comm。此时玩家注意力在操作上，只能接收**短、情绪化、可忽略**的信息，所以 comm 均长只有 41.6 码元。
3. **为什么会变成这样** →（战后/空闲时给）档案、拾取、邮件。此时玩家愿意读长文，所以档案均长 371.9 码元。
4. **到底谁在操纵一切** →（跨周目给）NG++ 才解锁的第三阵营线。

这条链的本质是：**信息的推送时机 = 玩家的消化能力**。不是「越重要的信息越早给」。

### 4.2 四条主线的揭露节奏表

| 揭示项 | 主载体 | 触发条件（可验证方向） | 为什么排在这个位置 | 等级 |
|---|---|---|---|---|
| **Coral 是什么** | comm 先给「现象」（红色粒子、异常通讯、能说话的东西），档案后给「定义」 | comm 触发绑定任务进度；档案触发绑定 ArchiveParam 的解锁行 | 先让玩家在玩法上遇到它（它会当你的雷达/它会影响敌人），再解释 | B（结构）/ C（解读） |
| **伊比斯之火（Fires of Ibis）发生了什么** | 档案长文 + 旧时代遗民角色的口述 | ArchiveParam 51 条日志中相当一部分为该主题 | 属于「历史」，不影响当下操作，放最便宜的可选通道 | C |
| **强化人改造的代价** | 任务简报 + comm（对主角本人的暗示） | 简报文本（ミッション概要 67 条）在序盘即出现 | 主角自身的处境必须尽早建立，否则玩家没有动机 | C |
| **幕后势力是谁** | comm 的阵营广播 + NG++ 专属任务链 | 第三结局要求通关竞技场后开启 MIA / Regain Control of the Xylem / Coral Release | 与「多周目结构」绑定：只有玩到第三周目才有资格知道 | B（Fextralife）/ C |

### 4.3 分期的「代价」

分期揭露意味着**第一次通关时玩家必然不理解结局**。AC6 用多周目把「不理解」变成**设计好的第二次阅读**——第三结局直接把视角换成对立阵营（IGN：新剧情线从对立阵营视角展开）。这是把「叙事理解」做成了**可重复消费的内容**，也是它敢把大量信息塞进可选通道的原因。

## 7. 分支如何与玩法耦合

### 7.1 分支的可见载体：任务列表的增减（而不是过场）

| 机制 | 玩家可观察到的事实 | 等级 |
|---|---|---|
| 决策任务以**两份同时出现**的简报挂在 Sortie 菜单，带专用图标 | 是 | B（IGN） |
| 两份简报**都可以进去听**，听完可以无成本退出、再去听另一份 | 是 | B（IGN） |
| 确认执行一份后，**另一份从菜单消失** | 是 | B（IGN / Fextralife） |
| 已完成的决策任务进入 Garage 的 Replay 列表，未做的**在列表里缺失**——这就是玩家"看见自己选了什么"的方式 | 是 | B（Fextralife） |
| 用暂停菜单的「Replay Mission」重打不会改变已锁定的分支结果 | 是 | B（Fextralife） |

### 7.2 为什么这样做更好（四段式）

**设计意图**：让「选择」在**不增加演出成本**的前提下变得可感知、可存档、可回放。

**实现手段（可观察的）**：
1. 选择被建模成一个**决策组**：一组互斥任务 ID。玩家完成其中一个 → 往存档里写一个「已完成任务」标记 → 另一个任务的可用性由数据表反推为 false。
2. 实测数据支持这个模型：MissionParam 有 **111 行任务行**，而 ミッション名 / ミッション概要 / ミッション目標 三张文本表**各只有 67 条**。差 44 行说明 MissionParam 里混有非主线条目（训练/竞技场/其他），而**主线任务量级 ≈ 60 余条**。**任务是一张可以被增删的表行，不是一个被写死的剧本节点。**
3. 决策任务在数据上就是**两行同时存在**，因此「同时挂出两份简报」不需要任何特殊代码——只需要查询「该决策组是否已有任一任务被完成」。
4. 实测佐证任务表的行 ID 是**分段结构**（2010–2250 一段、3011–3500 一段、4000–4200 一段、5010–5110 一段、6000–6020 一段，另有 7900–7990 十行、9001/9100、9200–9206、9300–9331、9400–9416 等块），分段与章节/内容类型对应（C 级解读）。

**玩家体验/结果**：
- **可感知**：菜单里少了一个任务，玩家自己发现。
- **可验证**：Garage Replay 列表里少了哪几条任务，就是「我还没走过的路」。
- **零演出成本**：不需要为主角的反应做任何动画。

**可复用结论**：把「选择」实现成**资源可用性**（任务 A 可用 / 任务 B 不可用），而不是实现成**演出分支**，是把叙事分支接到玩法循环上的最便宜做法。它天然可存档、可回放、可做成就（Stargazer 全任务成就就是"全表清空"）。

### 7.3 分支与构筑的耦合（本作最狠的一步）

分支不只是剧情，还**给专属机体部件**：
- Liberator of Rubicon 线 → HAL 826 套（IB-C03 系列）
- Fires of Raven 线 → ALBA 套（EL-P 系列）
- NG++ / ALLMIND 线 → 通过「Regain Control of the Xylem」的容器拿到 Coral 导弹与 Coral 护盾

**意义**：AC6 是一款**装配驱动**的游戏（EquipParamWeapon 284 行 × 1556 字节，是本机武器表规模）。把专属部件挂在分支上，等于把「选边」翻译成「我下一周目玩什么构筑」。叙事决定因此变成了**玩法决定**，这是纯演出分支做不到的。

## 8. 碎片化 vs 可达性：魂系「不给答案」与 AC6「有人一直在跟你说话」的差别

| 维度 | 魂系做法 | AC6 做法 | 本机可实测的对应物 |
|---|---|---|---|
| 世界史 | 物品描述碎片 + 环境叙事，**无人主动讲** | 档案长文（51 条 / 均长 372 码元）+ 场景拾取 | ArchiveParam 57 行；アーカイブ内容.fmg 51 条 |
| 当下指令 | 几乎没有指令层 | **战斗中通讯持续投喂** | TalkParam 6013 行；会話.fmg 5965 条 |
| 玩家确定性 | 不知道下一步该干嘛是常态 | 永远知道下一步打哪（任务列表） | MissionParam 111 行 + 简报文本 67 条 ×3 张 |
| 长文本入口 | 物品描述（被动、短） | 档案（主动打开、长） | アーカイブ内容 均长 371.9 vs 武器説明 均长 204.7 |
| 关键区别 | **信息是奖励**（找到了才有） | **信息是陪伴**（有人一直在讲） | 会話文本池 = 全部菜单文本池的 58.3% |

**平衡手法（三条，C 级）**：
1. **双通道冗余**：同一件重要事实会先在 comm 里给一个情绪化的钩子，再在档案里给完整版。玩家漏掉一边不会漏掉全部。
2. **档案和通讯用的是两条独立的资源管线**（不同 FMG 文件、不同表），因此可以独立追加、独立本地化、独立排期。
3. **不可达的内容不进主线**：第三结局的知识被锁在 NG++，等于把「最碎的信息」放到「玩家已经证明自己会玩」的位置——**用周目数当作信息可达性的门槛**。

## 9. 分析三问

### 问 1：如果主角开口说话会怎样？

| 维度 | 变化 |
|---|---|
| 装配系统 | 必须维护「说话人的身体与脸」，换装成本从「换模型」升级为「换角色形象」 |
| 分支 | 每个决策都要写主角的反应并配音 → 决策组数量必须大幅削减 |
| 本地化 | 台词表要新增一个高频说话人，文本池与配音预算同时上升（本作台词池已占全部菜单文本的 58.3%） |
| 叙事收益 | 角色弧光成立，结局的"人味"回到主角身上 |
| **设计空间边界** | 说话主角 = 换取弧光，付出**分支数量 × 演出成本**。AC6 选的是「多分支、零主角演出」这一端 |

### 问 2：如果把通讯语音全部换成文字日志会怎样？

| 维度 | 变化 |
|---|---|
| 成本 | 配音预算归零（这是唯一省下的钱）；文本写作成本不变 |
| 送达率 | **崩塌**。comm 的 5965 条台词分布在约 60 余个任务的战斗中；改成战后日志，等于要求玩家在 60 次任务结算后各读约 89 条文本 |
| 时间压力 | 目前台词是「边说边打」，改成日志后玩家可以按自己的节奏读，**信息吸收率反而上升**，但节奏断裂 |
| 设计空间边界 | 这是「叙事密度 vs 玩家耐心」的滑块。日志化会让 AC6 的叙事从**沉浸式广播**变成**魂系档案式考古**——而它已经有一模一样的第二通道（档案 51 条长文） |
| 结论 | 两条通道不是替代关系，是**分工关系**：comm 管情绪与紧迫感，档案管世界史 |

### 问 3：如果只有一个结局会怎样？

| 维度 | 变化 |
|---|---|
| 叙事结构 | 决策任务对失去意义 → MissionSystemMsgAnswerParam 的 40 条应答记录失去落点 |
| 玩法 | 专属部件（HAL 826 / ALBA / Coral 武器）失去获取理由，装配表的"顶配"变成单线 |
| 内容生命周期 | 三周目结构消失 → 单次通关即可看完，**世界史只能靠可选档案补齐**，而档案是可选通道（送达率低） |
| 收益损失 | NG++ 的第三阵营线（IGN：从对立阵营视角展开的新剧情）整段消失 |
| **设计空间边界** | 结局数决定了「内容可重玩倍数」。AC6 用 3 结局 × 分支任务 × 专属部件把一次 60 余任务的内容变成三次不同体验——**这是低成本延长内容寿命的标准做法** |

## 10. TA 转化：叙事系统的技术实现

> 这一节是给 TA 岗准备的。目标：把上面所有"叙事效果"翻译成可交付的系统。

### 10.1 四个子系统

| 子系统 | 输入数据 | 需要实现的核心状态机 | TA 具体交付物 |
|---|---|---|---|
| **对话/语音触发** | TalkParam 行（说话人 + 文本 id + 触发条件）；文本在独立 FMG | 触发条件是一个谓词（任务进度 / 区域 / 时间 / 事件标记）→ 一条**台词播放请求** | 台词资产管线：CSV/pipeline 导出 → 字表（StringTable）→ 音频行（VO asset）→ 运行时按 id 取；字幕行的**行长约束检查器**（见 10.3） |
| **任务状态机** | MissionParam 111 行；每个任务是一行 | 状态：Locked / Available / Active / Completed / Failed / Skipped；**可用性由数据表反推**，而不是硬编码 | DataTable + 一个纯数据驱动的可用性求解器（输入：已完成集合 + 决策组表；输出：本次可接任务列表） |
| **分支存档标记** | 决策组 = 互斥任务 ID 集合 | 存档只需存 **Set<CompletedMissionId>**（位图或 id 集合）+ 版本号；**不需要**存任何过场 flag | 存档序列化 + 版本迁移 + 校验；一个「决策组一致性」断言（同一组不允许出现两个已完成） |
| **过场调度** | CutsceneGparamTimeParam(4) / WeatherParam(1) / MapIdParam(74) / ReplaceSfxParam(38) / TimezoneConvertParam(7) / GarageCutsceneParam(3) / SoundCutsceneParam(105) | 过场 = 一次 **LevelSequence 播放 + 环境参数覆写 + 音频替换** | LevelSequence 的 Track 模板（环境/天气/音频参数暴露为轨道）；地图分段与天光/雾/体积云的参数包 |

### 10.2 关键洞察：**分支不落在过场里，落在数据可用性里**

这是 P3 最值得抄的一条工程结论（C）：

- 传统做法：决策 → 播一段不同的过场 → flag 存档 → 后续对话不同。
- AC6 做法：决策 → **一个任务 ID 进入已完成集合** → 另一任务行反推为不可用 → 后续整条任务链由数据自动分叉。
- 好处：分支数量可以随「表行数」线性增长，而演出成本近似为零；成就（全任务）也变成一次表查询。

### 10.3 本地化的 TA 视角（本报告唯一有实测数字的地方）

实测英文与中文的同一批 FMG：

| 文件 | 英文串数 | 英文字符 | 中文串数 | 中文字符 | 中/英 字符比 |
|---|---|---|---|---|---|
| 会話（台词池） | 5965 | 248,181 | 5964 | 91,788 | **37.0%** |
| メニューテキスト | 1721 | 31,998 | 1720 | 21,091 | 65.9% |
| アーカイブ内容 | 51 | 18,965 | 51 | 5,911 | 31.2% |
| ミッション概要 | 67 | 7,730 | 65 | 2,534 | 32.8% |

**可交付结论**：
1. 英文台词池均长 41.6 字符/条，中文 15.4 字符/条——**同一行的中文字符数约为英文的 37%**。字幕框宽度按英文设计是安全的，但**中文更容易「一行塞不满」**，真正的风险在换行与断句规则（中文不能按空格断）。
2. 条目数几乎一一对应（5965 vs 5964），说明**本地化是整表替换**，不是重排。TA 要保证的是 **id 稳定**——任何在英文表里插入/删除一行的操作都会整体错位。
3. **字幕/语音长度校验器**应当作为 CI 环节：对每一条，取英文与目标语言的字符数，断言目标语言 ≤ 英文的 X%（实测中文在 31–37%），并标记异常项。

### 10.4 过场调度的实测边界

- CutsceneGparamWeatherParam **只有 1 行**（rid=0）。→ 天气在过场层几乎不是可变量，别照抄成"每个过场配一套天气"。
- CutsceneMapIdParam 74 行、SoundCutsceneParam 105 行、CutsceneReplaceSfxParam 38 行。→ **音频替换**这一层比环境层丰富得多，说明"过场的差异化"主要靠音频而不是视觉环境。
- CutsceneGparamTimeParam 4 行，ID 为 0 / 95150000 / 99000000 / 99950010，其中后三个是明显的**哨兵值**（形如 99xxxxxx）。→ 时间参数是**极小枚举 + 特殊语义值**，不是连续参数。

（以上均为实测计数 + D 级语义推断。）

### 11.4 mod 侧对照（说明叙事表的可追加性）

命令：对 van / mob / reibis 三份 regulation-bin 的同名表逐行字节比较。
~~~

MissionParam 内容不同的行 rid = [2010, 9200, 9201, 9202, 9203, 9204, 9205, 9206]
   rid=2010 差异槽位(字节偏移, van, mob): [(284, '94c3c901', '00000000')]
   rid=9200 差异槽位(字节偏移, van, mob): [(8, 'a0bb0d00', '80969800'), (44, '00000000', '10270000'), (72, '0000803f', '0000803e'), (80, '0000803f', '0000803e'), (216, '00000000', 'b47f8e06'), (220, '00000000', 'a0860100'), ...]
~~~

**可由这段实测得到的结论（B）**：
1. 台词表是**可追加的扁平表**：mod 在 van 的 6013 行之外追加了 12 行（reibis 追加到 6027 行），**所有原有行的字节完全一致**（行数据不同 = 0）。→ 追加台词不需要重排既有数据，这对 mod 与 DLC 都是好消息。
2. MissionParam 只有 8 行被改动，其中一行是任务 rid=2010（序号最小的主线任务），且改的是末段的一个值（被置 0）；另外 7 行是 9200–9206 这一整段。→ 改动是**定点**的，不是全表重写。

注意：md5 层面 20/20 张叙事表都"不同"，但逐行字节比较显示多数表的**行数据完全相同**（差异来自重新序列化，例如行数/ID 顺序/尾部布局），**不能**用文件 md5 差异推断内容改动。这条也是实测教训。
