# P9 · 美术方向与渲染表现（TA 重点）拆解报告

> 读者定位：大四、目标技术美术（TA）、计划从策划岗入门。
> 证据分级：**A** = 游戏内可观察 / 官方公开；**B** = AC6 专用 paramdex 定义 + 本机 .param 实测值域复核 / 社区实测；**C** = 同类引擎与管线的合理推断；**D** = 不确定，必须写明验证方法。
> 本报告所有"实测"字样，均可在第 12 节找到对应命令与原始输出片段。

## 0. 结论先行（TA 视角的 10 条）

1. **AC6 的美术方向不是"画出来"的，是"排出来的"**：全篇最重要的发现是 `LoadBalancerParam`（33 行）——它把 19 个画质项（Bloom / Glow / AA / SSAO / DOF / MotionBlur / MotionBlur迭代 / LightShaft / ShadowBlur / **ParticleHalf** / SFX反射 / SFX水面 / SFX Glow / SFX畸变 / 软粒子 / SFX光轴 / 效果距离缩放 / 动态分辨率 / 阴影级联0半分辨率）做成了**可按 FPS 自动升降的阶梯**，并配了完整的迟滞（连续 5 帧低于阈值才降、连续 20 帧高于阈值才升、降后冷却 30 帧、升后冷却 10 帧）。**风格是首帧定死的，性能是运行时谈出来的。**（B）
2. **玩家自定义涂装靠的是"5 层材质栈 + 参数覆写"，不是重做贴图**：`PlayerMaterialPresetParam`（46 行）给 0~2 层（素体铁 / 底漆 / 涂装后状态）、`PlayerWeatheringTexPresetParam`（24 行）给 3~4 层（剥落 / 锈），`MaterialExParam` 里躺着 `CHG_1stlayer / CHG_3rdlayer / CHG_4thlayer`、`Peeling_Int / Rust_Int / Dirty_Int / Damage_Int` 这些真实参数名。**美术只需要在模型上画一张"部位遮罩"，剩下的全是数据。**（B）
3. **色彩不是 RGB，是"5 通道分区"**：`PlayerColoringPresetParam`（6 行 × 392 字节）每个 slot 存 `Base / Sub / Support / Optional / Device` 五组 RGBA；`MaterialExParam` 里对应 `Color_Main / Color_Sub / Color_Support / Color_Optional / Color_Joint / Color_Device / Color_Eye`。**玩家换色 = 换一组 uniform，零贴图开销。**（B）
4. **"看不清但不难受"的核心手法是把后处理当分级器而不是滤镜**：`Zoomblur` 表（7 行）为 6 种情境各配了一组参数——普通 boost / 大 QB / 坦克 QB 攻击 / 坦克 QB 踏击 / 高速移动 / カタパルト事件。大 QB 的 `Offset=0.005`，普通 boost 只有 `0.0025`；而"中心薄め値"从 boost 的 `-1` 收到 QB 的 `-0.1`——**速度越快，屏幕中心留得越干净**。（B）
5. **`GraphicsParam.ShadowFixedFov = 45.0°`**：阴影相机用固定 FOV，不跟随玩家相机 FOV 变化。这是典型的阴影预算技巧——FOV 一变，级联的 texel 密度就要重算，固定住就能用一套预算吃下全部镜头（含开镜）。（B）
6. **命中反馈是一张二维矩阵表，不是一个特效**：`HitEffectSfxParam`（71 行 × 240 字节）= 25 列（斬撃/刺突/打撃/爆風/弾丸 × S/M/L/LL/LLL），行是"攻击属性 × 目标材质"概念（`HitEffectSfxConceptParam_Concept.tdf`：铁 / EN绿 / コーラル / パルス / レーザー / プラズマ × 汎用着弾 / 重鉄 / 盾エネルギー）。**金属面命中做满 5 档（201000–201009 共 10 个不同 ID），能量盾面命中只复用 2 个 ID（990902/990903）**——美术预算被明确投在玩家可视度最高的通道上。（B）
7. **帧率与频率闸门是美术的一部分**：`GraphicsParam` 里 `HitInsDamageNearSfxNumMax = 1`、`HitInsDamageNearSfxDist = 50 m`（50 m 内最多 1 个近失 SFX）、`BulletMultiFrameHitSfxIntervalTimeSec = 0.2 s`（多段命中 SFX 最小间隔 200 ms）。**连射武器若不做这个，命中音画会糊成白噪音。**（B）
8. **LOD 是按"物体尺寸分桶 + 按平台缩放曲线"两段式做的**：`PartsDrawParam`（152 行）用 100/200/350/∞ m 四级 + `drawDist 1600 m` + `shadowDrawDist 350 m` 管 AC_PC/AC_NPC；`LoadBalancerDrawDistScaleParam_*` 用 22 级 Lv 缩放曲线管平台差异——**ps5/xsx 全 1.000（不缩），ps4 最狠的一条曲线从 0.962 线性衰减到 0.475，xb1/xss 有一组是整体 0.600**。而 `PartsDrawParam_ps4/ps5/xb1/scarlett` 的 AC 行**完全一致**——平台差异不在 LOD 表里，在 LoadBalancer 表里。（B）
9. **"幻影"（残像）是一等公民**：`PartsDrawParam_LodType.tdf` 明确列出 `ローカルプレイヤー(8) / リモートプレイヤー(9) / 幻影(10)`；`LoadBalancerDrawDistScaleParam` 的 DevName 也有「幻影」专档；`LoadBalancerNewDrawDistScaleParam` 有 `ローカルプレイヤー / リモートプレイヤー / 幻影` 三行 + `0.75 / 0.6 / 0.5 / 0.4 / 0.3` 五档缩放。**高速残像走的是专门的降级通道，不是复制一份完整角色。**（B）
10. **超巨型结构的做法是"捕获 + 转写 + Imposter"**：`AssetSlod*` 四个枚举定义了 SLOD 管线——`SLOD対象外 / そのまま結合 / 転写元 / 転写先 / インポスター / 最終結果`，纹理尺寸 64→4096，捕获角 20/30/45/90 度，捕获方向数 16/36/64。**这就是"机甲只有 10 m、建筑却有 1000 m"却不爆显存的答案。**（B）

## 1. 视觉定位：一句话 + 可执行要素

**一句话**：**低饱和度的工业废土底色（黄灰沙尘 / 蓝灰冰原 / 褐灰厂房）+ 极高亮度的窄谱能量光（EN 绿、Coral 红、等离子青白）**，用"亮度差的悬殊"而不是"色相的热闹"来制造工业硬科幻的可读性与力量感。

### 1.1 可执行的五要素

| 要素 | 具体做法 | 本地证据 | 等级 |
|---|---|---|---|
| **色调范围** | 环境主色集中在低饱和黄灰 / 蓝灰 / 褐灰三段；颜色信息主要由天空盒资产承载（时段化），而非全局调色 | `SkydomeAssetParam` 47 行的行名 = 场景×时段：`氷原_燃料基地_夕(18:30)白夜`(3300030)、`氷原_燃料基地_夜ver1`(3300040)、`大氷原_朝`(3600000)、`A層_ビックブリッジ_昼A`(10100010)。**时段/天气是资产，不是 GI 参数** | B |
| **对比度策略** | 亮部交给自发光（可超白），暗部交给低照度环境 + 体积雾；中间调被 tone mapping 收窄，形成"暗灰底 + 少量纯白/纯色高光"的分布 | `MaterialExParam` 里 `Emissive_Power / Emissive_Strength / [A_C]_Emissive_Glow_Int / Laser_Threshold` 独立存在，说明自发光有独立的超白与阈值通道 | B |
| **材质倾向** | 高金属度 + 中高粗糙度为主，靠"环境反射的冷/暖偏移"讲金属；材质感由 3 个标量控制（`Shininess / Metalness / Glow`） | `PlayerMaterialPresetParam` 实测：`Shininess` 步进 0.2（0~1.0 共 6 档）、`Metalness` 步进 0.2（6 档）、`Glow` 0.1→4.5 共 10 档 | B |
| **形态语言** | 方块化装甲板 + 外露液压关节 + 天线/散热片等细长件；"工业感"来自可辨识的机械功能件而不是雕花 | `DecalParam` 弹痕按武器分 8 类（步枪/机枪/巴祖卡/加农/激光步枪/激光加农/等离子/导弹，rid 800000–800007）；`MaterialExParam` 有 `CaterpillarScroll`（履带滚动）、`c5900_Heatsink_Intensity`（散热片）等真实部件专用参数 | B |
| **尺度关系** | 用"尺寸分桶"而不是"统一 LOD"跨尺度：角色 20/40/100/200/500/1000+ m 六桶；FNR 远景资产 11-30 / 31-60 / 61-100 / 101-200 / 201-500 / 501-1000 / 1001-1500 / 1500+ m 八桶 | `PartsDrawParam` Developer Names 原样给出这些分桶；`GrassLodRangeParam`（15 行）另给草丛三档 0-150 / 150-1000 / 1000-5000 m | B |

### 1.2 一句 TA 化的总结
> 工业硬科幻的渲染公式 ≈ **低饱和 albedo（环境）+ 少量高动态 emissive（信息）+ 大量尺寸分桶（性能）**。
> 前两项决定了"看起来像不像"，第三项决定了"能不能跑 60"。AC6 把三件事都写进了 param 表。

## 2. 材质体系

### 2.1 ★ 玩家自定义涂装的实现（本报告最核心的机制）

**设计意图**：让玩家在几分钟内改出"我的机"，但不能让美术为每个玩家的配色重做贴图，也不能让材质实例数量爆炸。
**实现手段**：**5 层材质栈 + 遮罩 + 参数覆写**。

| 层 | 表 | 内容 | 实测字段/值 |
|---|---|---|---|
| **L0** | `PlayerMaterialPresetParam` | 素体铁（基本鉄） | 字段 `TexIdLayer0` |
| **L1** | 同上 | 底漆（基本ベースペイント） | `TexIdLayer1` |
| **L2** | 同上 | 涂装后状态（基本塗装後の状態） | `TexIdLayer2` |
| **L3** | `PlayerWeatheringTexPresetParam` | 涂装剥落贴图（塗装剥がれTex） | `TexIdLayer3`，实测值域 `-1 / 92041 / 92044 / 92049` |
| **L4** | 同上 | 锈贴图（錆Tex） | `TexIdLayer4` |

- **标量覆写**（决定"什么材质"）：`Shininess / Metalness / Glow` 三个浮点。实测 `PlayerMaterialPresetParam` 是 **6×6 的网格 + 10 档光量**：
  - 行 0–35：`Shininess ∈ {0,0.2,…,1.0}` × `Metalness ∈ {0,0.2,…,1.0}`（Developer Names 逐行写着"Glossiness: 0.6 Metallic feel: 0.4"），`Glow` 恒为 1.0；
  - 行 90–99：`Shininess=Metalness=0`，`Glow ∈ {0.1,0.5,1,1.5,2,2.5,3,3.5,4,4.5}`（Developer Names 写着"Light intensity: 2.5"）。
  - **注意这是个"量化滑条"设计**：玩家在 UI 上拉的是连续滑条，落到数据里是 46 个枚举行之一。这样着色器只需要按行 ID 取一组 uniform，不需要为每个玩家编译/实例化新材质。
- **旧化是"预设 + 逐层材质改写"**：`PlayerWeatheringTexPresetParam` 24 行 = `劣化無し(0)` + `塗装剥がれ` A/B/C 各 4 档（边缘剥落/小/中/大）+ `錆` A/B 各 4 档（極小/小/中/大）+ `汚し` 3 档。每行除了强度 `Peeling_Int / Rust_Int`，还额外带 **`CHG_1stlayer_Shininess / CHG_1stlayer_Metalness / CHG_3rdlayer_Shininess / CHG_3rdlayer_Metalness`**——即"漆掉了露出底下的铁"这件事，是靠**改写第 1 层和第 3 层的光泽/金属度**实现的，不是靠贴图叠色。实测样例：rid=0 无劣化 `Peel=0 Rust=0 CHG_1st=(0.5,1.0)`；rid=5 边缘剥落 B `Peel=1.15 CHG_1st=(0.8,0.7)`；rid=21 汚し小 `Peel=1.26 Rust=1.11 CHG_1st=(1.0,0.25)`。
- **颜色是 5 通道分区**：`PlayerColoringPresetParam` 6 行 = 6 个预设色板（Developer Names：`default / red / blue / yellow / peach / green`），每行 392 字节 = **14 个 slot × 28 字节**，每个 slot = `PatternID(1) + MaterialProperty_0(1) + MaterialProperty_1(1) + reserved(5) + Base RGBA / Sub RGBA / Support RGBA / Optional RGBA / Device RGBA`。实测 rid=0 全 slot `Base=(128,128,128,255)`、rid=1 `(255,0,0,255)`、rid=3 `(255,255,0,255)`、rid=4 `(255,96,160,255)`。
- **迷彩是独立一层**：`PlayerCamouflagePattern`（30 行 × 16 字节）= `Small / Medium / Large` 三个尺度 + `Slot0..3_enabled` 位掩码；对应材质参数有 13 个 `Camouflage_*`（`Texture / TexSize / Resize / Rate / Transparency / Refraction / Nonreflex / NonMetal / Falloff / FalloffPower / Emissive / Main / Sub / Support / Optional / Joint`）。
- **材质参数注册表证明这套是"参数驱动"**：`MaterialExParam` 212 行 / **198 个唯一参数名**（实测所有行的 `materialId` 均为 -1、值均为 `(0,0,0,0,1)` 默认值——说明这张表在本作里主要作**命名注册表**用，不是逐材质覆写数据）。其中与涂装直接相关的有：
  `Color_Main / Color_Sub / Color_Support / Color_Optional / Color_Joint / Color_Device / Color_Eye`、`Shininess`、`Metalness`、`CHG_1stlayer / CHG_3rdlayer / CHG_4thlayer`、`Chg_Albedo_1..4 / Chg_Metalness_1..4 / Chg_Normal_Shininess_1..4`、`Peeling_Int / Rust_Int / Dirty_Int / Dirty_range_Int / Damage_Int / Damage_Rate / Damage_em_power / Burnt_Int`、`MarkingTexture / MarkingTexIndexOffset / marking_1..5_Int / End_of_Decal_Tex`。

**玩家体验/结果**：换涂装是**即时**的（只换 uniform，不重载贴图），而且旧化/剥落是"改变了表面材质属性"而不是"盖了一层脏图"——所以锈迹在高光下会正确地变暗、变粗糙。
**可复用结论**：**"玩家可定制"不等于"程序化生成贴图"。最省的做法是：美术画一张 5 通道分区遮罩 + 一组材质参数，程序只负责把玩家的 5 组 RGBA 和 3 个标量塞进 uniform。** 这套的等价 UE5 实现是 Material Instance + 参数集（MPC），关键是把可调项**枚举化/量化**，避免材质实例数量随玩家数线性增长。

**待验证（D）**：`MaterialProperty_0 / MaterialProperty_1` 两个字节具体指向哪张表，我无法从数据直接读出。最可能是 `MaterialProperty_0 → PlayerMaterialPresetParam` 行 ID、`MaterialProperty_1 → PlayerWeatheringTexPresetParam` 行 ID，但本机没有存档格式定义，属推断（C）。
**14 个 slot 中只有 12 个对应装备槽**（头/核心/腕/腿/推进器/FCS/发电机/左右手武器/左右背武器/扩展），另外 2 个 slot 语义未验证（D）。

### 2.2 金属 PBR 的三条实测证据

| 命题 | 证据 | 等级 |
|---|---|---|
| 金属度是 0~1 连续量、并按部件可分别设置 | `PlayerMaterialPresetParam` 网格步进 0.2；`NpcMaterialParam`（417 行 × 28 字节）按 `materialParamId → materialId` 给敌方逐材质覆写 4 个 f32（`Param0..Param3`） | B |
| 粗糙度/光泽通道独立于 albedo | `MaterialExParam` 的 `Chg_Normal_Shininess_1..4` 说明**法线的 alpha 通道携带 shininess**（魂系/FS 引擎惯例：Normal_Shininess 打包） | B（字段名 A 级，打包方式 C 级） |
| 划痕/磨损**不靠**新增贴图通道，而靠"改层" | `CHG_1stlayer / CHG_3rdlayer / CHG_4thlayer` + `Peeling_Int / Rust_Int` 而**没有**一个独立的 "Scratch_*" 参数 | B |

### 2.3 湿润 / 破损 / 弹痕

**湿润（Wet）**：`WetAspectParam`（20 行 × 32 字节）字段 = `baseColorRGB(u8) + baseColorA%(f32) + metallic(u8) + metallicRate(f32) + shininessRate(f32) + shininess(u8)`。实测：
- rid=7「鉄の体」：`rgb=(155,155,175) A=1.00 metallic=255(满) metallicRate=1.00 shininessRate=1.00 shininess=190`
- rid=6「敵対ゲスト用」：`rgb=(60,20,10) A=0.50 metallicRate=0.10 shininess=20`
- rid=11「[Cutscene] Tar」：`rgb=(5,5,10) A=1.00 shininessRate=1.00 shininess=150`
→ **湿润/污渍是"材质参数覆写层"，不是第二套贴图**。同一个机甲模型可以同时是"湿的"和"锈的"，因为二者作用在不同通道（Wet 改 baseColor/metallic/shininess，Weathering 改层遮罩与层材质）。
`GraphicsParam.CharaWetDecalFadeRange = 0.6` 是角色受湿时的贴花淡出范围参数。

**弹痕（DecalParam，248 行 × 252 字节）**——这是本作技术含量最高的一张表：

| 能力 | 字段（paramdex 名） | 实测统计 |
|---|---|---|
| 延迟贴花 | `useDeferredDecal` | **247 / 248 行 = 1**（贴花几乎全部走延迟 G-buffer 路径） |
| 玩家涂鸦式贴花 | `usePaintDecal` | **89 / 248 行 = 1**，其中 800000 步枪 / 800001 机枪 / 800004 激光步枪 / 800005 激光加农 / 800006 等离子 / 800007 导弹**弹痕的 `lifeTimeSec` 均为 10.0 s**，与 `GraphicsParam.PaintDecalFadeOutTimeSec = 10.0 s` 同值 |
| 混色 | `blendMode`（TDF：1=半透明，2=乘算） | 半透明 214 行 / 乘算 34 行 |
| 法线 | `bUseNormal` | 196 / 248 = 1 |
| 自发光（激光灼痕会亮） | `useEmissive` + `emissiveValueBegin/End/Time` + `emissiveColorRGB` | 173 / 248 = 1；`emissiveTime` 实测 `0s(80行) / 2.0s(68行) / 3.0s(22行) / 1.0s(9行)` |
| 视差（POM） | `usePom / pomHightScale / pomSampleMin/Max` | **0 / 248 行 = 1 —— 本作完全不用 POM**（性能优先的明确取舍） |
| 六通道贴花材质 | `mask / diffuse / metallic / normal / height / emissive TextureId` + `maskScale / metallicScale / siniScale` + `diffuseColorRGB` | 实测 800000 行 `mask=4001000 diffuse=4001000 normal=4001000 emissive=4001000 metallic=10 height=-1` |
| 稀疏化（Draw Call / 重叠保护） | `bDistThinOutEnable / distThinOutCheckDist / CheckAngleDeg / distThinOutMaxNum / CheckNum / thinOutOverlapMultiRadius / thinOutNeighborAddRadius / thinOutOverlapLimitNum / thinOutNeighborLimitNum / thinOutMode` | 只有 **4 / 248** 行开启；`thinOutMode` 全部 = 0（"削除"） |
| 随机化 | `randomSizeMin/Max(％)`、`randomRollMin/Max`、`randomPitchMin/Max`、`randomYawMin/Max`、`randVaria_Diffuse/Mask/metallic/Normal/Height/Emissive`（各 4 bit）、`bAlignedTexRandomVariationEnable` | 存在；意义 = 同一个弹痕贴图用 UV 随机 + 通道变体凑出"不重复" |
| 贴花生命 | `lifeTimeSec / fadeInTimeSec / fadeOutTimeSec / priority` | 寿命分布：`4.0s × 85 / 10.0s × 47 / 0.0(=不限) × 39 / 5.0s × 31 / 2.0s × 21 / 3.0s × 20`；`priority` 只有 -1 与 0 两种值（38 行非 0） |

**弹痕按武器分型**（Developer Names 原文）：`800000 【攻击】步枪_弹痕贴花 / 800001 机枪 / 800002 巴祖卡 / 800003 加农 / 800004 激光步枪 / 800005 激光加农 / 800006 等离子加农 / 800007 导弹 / 800008-800010 敌方 Stigro 小/大/扩散激光着弹`。另外表里还有 `470000 强袭扬陆舰 激光熔痕`、`630000/630001 次世代原型AC登场 铁 拖拽痕迹 前后` 这类**叙事专用贴花**。

**玻璃**：`MaterialExParam` 有 `Device_Glass_Alpha_Int`（设备玻璃透明度）；`NpcPartsParam`（110 行 × 60 字节）有 `isShieldGuardEnable:1 / isPaGuardEnable:1 / isPhysGuardEnable:1 / isBulletForceForceRicochetSfx:1`（**强制跳弹 SFX**）——即"打不动"的反馈是数据开关而不是靠材质硬度模拟。

### 3.1 模块化与"不穿模"

| 机制 | 证据 | 说明 |
|---|---|---|
| **挂点（dummy poly）体系** | `AttachObj_Pc`（4 行 × 544 字节）= 8 个 `ObjName[32]`（関節名）+ 8 个 `attachDmyId`（アタッチダミポリID）；`ThrustersParam_PC`（103 行 × 700 字节）每个推进器挂点都有 `DummyID` + `IsFollowDmyPoly` | 模块之间靠**命名的挂点**连接，而不是靠坐标。美术改模型时只要挂点名字不变，参数表全部复用 |

| **穿模控制** | 未在本机数据中找到直接证据（无部件包围盒表） | **D 级**。验证方法：查 `EquipParamProtector`（121 行 × 900 字节）/ `EquipParamWeapon`（284 行 × 1556 字节）是否存在碰撞/包围字段，或在游戏内用"全组合预览"实测穿模率 |

| LOD2-3 边界 / 游隙 | 350 m / 20 m |

| motionBlur_BorderDist | 300 m |

| DistantViewModel | 500 m / 20 m |

**尺寸分桶**（Developer Names 原样）：`キャラ用 小型(～20m)` lv01B=300 / `中型(～40m)` =600 / `大型(～100m)` =1200 / `特大(～200m)` =1600 / `超特大～500m` =1800 / `1000m～` =7500（drawDist 与 shadowDrawDist 都跑到 99999）。

**第二段：`LoadBalancerDrawDistScaleParam_*`（22 个 Lv 缩放列）**

| 平台 | 行数 | 实测 |
|---|---|---|
| **ps5** | 22 | 全部 1.000（不缩放） |
| **xsx** | 22 | 全部 1.000（不缩放） |
| **xss** | 22 | rid100-107 全 **0.600**（整体 60%） |
| **ps4** | 48 | rid200 序列 0.983→0.755；**rid400/404 序列 0.962→0.475（最低砍到 47.5%）** |
| **xb1** | 46 | rid100-107 全 **0.600**；另有 0.983→0.755、0.962→0.475 等序列 |
| **win64** | 无该表（在 van 的 regulation-bin 中不存在） | — |

**`LoadBalancerNewDrawDistScaleParam_*`**（字段 = `DrawDist_LvBegin/End + ScaleBegin/End + ShadwDrawDist_LvBegin/End + ScaleBegin/End`）的 DevNames 给出档位语义：`0 默认(不缩放) / 1 ローカルプレイヤー / 2 リモートプレイヤー / 3 幻影 / 4=0.75 / 5=0.6 / 6=0.5 / 7=0.4 / 8=0.3 / 10 Chr小 / 11 Chr中 / 12 Chr大 / 13 Chr特大 / 20 Map/Obj默认`。实测 `ps4` 与 `win64` 的 rid4 = `ScaleBegin 0.800 / ScaleEnd 0.750`、rid8 = `0.300 / 0.300`；而 `ps5/xsx/xss` 各自只有 1 行。**同一套 LOD 表 + 不同平台的缩放曲线 = 跨平台性能预算。**

**第三段：巨物（SLOD）** — `AssetSlod*` 四个 TDF：

| TDF | 取值 |
|---|---|
| `ASSET_SLOD_CONVERT_TYPE` | `SLOD対象外(0) / そのまま結合(1) / 転写元(2) / 転写先(3) / インポスター(4) / 最終結果(5)` |
| `ASSET_SLOD_TEX_SIZE_TYPE` | 64×64 / 128 / 256 / 512 / 1024 / 2048 / 4096 |
| `ASSET_SLOD_CAP_ANGLE_TYPE` | 20° / 30° / 45° / 90° |
| `ASSET_SLOD_CAP_DIR_NUM_TYPE` | 16 / 36 / 64 方向 |

→ **巨型建筑不是"做个低模"，而是"从 16/36/64 个方向、在 20~90° 仰角范围内捕获外壳，转写到低模，再生成 Imposter"**。"転写元/転写先"这组词说明存在**显式的转写配对**（高模指定为源、低模指定为目标）。这是"10 m 的机甲和 1000 m 的建筑同屏"能跑起来的关键。

### 3.3 材质实例化与内存分级

- `ChrModelParam`（62 行 × 12 字节）：`modelMemoryType` / `texMemoryType`（实测取值 0~4，分布 `{3:49, 4:7, 2:4, 1:1, 0:1}`）、`cameraDitherFadeId`、`isNoRayTracing`（**62 行全部 = 0**）、`rayTracingCullingMode`（全部 = 0）。

### 4.1 特效层级（可读性优先级）——从数据反推

`SpEffectVfxParam` 的 `playCategory + playPriority` 结构说明本作对 VFX 做了**分类 + 类内优先级**（0 类 671 个、3 类 50 个、4 类 41 个、7 类 19 个），配合 `LoadBalancerParam` 的 `sfxGlow / sfxDistortion / sfxReflection / sfxParticleHalf` 四个独立降级档。给出一个可复用的分层建议（C 级推断，但结构上被数据支持）：

| 层 | 内容 | 是否可降级 |
|---|---|---|
| L0 信息层 | 锁定框、Boss 招式预警、护盾命中、受击方向 | **绝不降**（`sfxGlow` 在所有平台上都保持高档位：实测 PS5/PS4/XB1 均为 21） |

| L3 装饰层 | 扭曲（`sfxDistortion` 实测 4 / 6 / 10 / 21）、水面交互（`sfxWaterInteraction`） | **首选牺牲**（PS4 类平台上 `sfxDistortion=4`，几乎是关） |

| 2100 | 坦克 QB 踏击 | 255 | 0 | **0.010** | -0.5 |
| 3000 | **高速移动** | 255 | 0 | **0.020** | -0.5 |
| 9000 | 【事件】カタパルト移动 | 255 | 1 | 0.010 | -0.5 |

**读法（这是本报告最能直接抄的一条）**：
1. **强度按"机动量级"单调递增**：boost 0.0025 → 大 QB 0.005 → 坦克 QB 0.010~0.015 → 高速 0.020。**8 倍跨度**。
2. **`CenterThin` 是"中心留白"**：普通 boost 用 -1.0（几乎不模糊中心），大 QB 收紧到 -0.1，高速移动 -0.5。**QB 是唯一一个"既要用强模糊表达爆发、又几乎不留中心遮挡"的动作**——因为 QB 的瞬间玩家需要立刻判断"我闪到哪了、下一个目标在哪"。
3. **`FixCenter` 是布尔**：boost / 大 QB / カタパルト = 1（模糊中心固定在屏幕中心），坦克 QB 与高速移动 = 0（中心跟随后处理参数漂移）。
4. **`GraphicsParam.ZoomBlur_ThresholdSpeedKmH = 100.0` + `InterpolationTime = 0.4 s`**：>100 km/h 才起、0.4 秒线性插值。**0.4 s 的插值是防"闪一下"的关键**——它让模糊变成"加速过程"而不是"跳变"。

### 6.2 体积雾 / God Ray 的真实开关

`GraphicsConfig_VolumetricEffectQuality`（paramdex 定义字符串，A 级字段名）：

```
fogEnabled / fogShadowEnabled / fogVolumeEdgeCorrectionLevel（双边上采样时的边缘补正等级）
fogVolumeResolution（雾体上采样处理的分辨率）
fogShadowSampleCountBias / fogLocalLightDistScale
fogVolumeSizeScaler / fogVolumeSizeDivider
fogVolumeDepthScaler / fogVolumeDepthDivider
fogVolumeEnabled（配置式雾体积）/ fogVolumeUpScaleType / fogVolumeUpScaleInTwoStageEnabled（两段上采样）
fogVolumeShadowEnabled
```

**每条都值得抄**：
- **按体积（Volume）布置雾**，而不是全局线性/指数雾 —— `fogVolumeEnabled` 说明可以只在某个峡谷/厂房内放雾；
- **雾体积有独立的 size 与 depth 缩放/除数**（`SizeScaler/Divider`、`DepthScaler/Divider`）→ 可以用"降深度切片数"的方式降成本，而不是把雾关掉；
- **两段式上采样 + 边缘补正** → 半分辨率雾体不会在几何边缘糊成方块；
- `fogLocalLightDistScale` 与 `LightingQuality.localLightDistFactor=0.75` 配套 → **雾里的点光源计算距离是被限制的**（雾里放 100 盏灯会爆炸）。

`LightingQuality` 的 `forwardPassLightingEnabled` 证实引擎**同时有前向与前向/延迟混合通路**（配合 `DecalParam.useDeferredDecal = 247/248`，说明主几何走延迟、需要特殊着色的走前向）。

### 6.3 "看不清但不难受"的具体手法

| 问题 | AC6 的解法 | 证据 |
|---|---|---|
| 沙尘里看不见敌人 | 不用提高环境亮度，而是**在敌人身上加信息通道**（自发光部件、锁定框、命中火花），并把环境压低 | `Glow` 档位在所有平台都 = 21 不降；`sfxGlow` 同 |
| 高速时看不清方向 | 径向模糊**中心留白**（`CenterThin`） | §5.2 |
| 雾里点光源爆掉 | `fogLocalLightDistScale` + `localLightDistFactor=0.75`；`localLightShadowEnabled` 单独开关 | GraphicsConfig_Volumetric/Lighting |
| 巨大的暗部空间（地下/厂房） | 靠自发光（设备/警示灯）+ 少量局部光；`localLightShadowSpecLevelMax=1` 限制局部光阴影等级 | GraphicsConfig_LightingQuality |
| 远近景层次不清 | 体积雾按 Volume 布置 + 两段上采样；远景用 FNR/SLOD Imposter 保持轮廓 | §6.2 / §3.2 |
| 阴影远处糊 | `shadowDrawDist = 350 m`（AC_PC）+ `shadowBlur` 档位 + `shadowCascade0ResolutionHalf` 可翻倍/减半 | §3.2 / §8.1 |

## 7. 可读性（Readability）

**结论**：AC6 的可读性**不建立在色相区分上，而建立在"亮度分层 + 轮廓 + 特效优先级"三层上**。

| 手段 | 机制 | 证据 | 等级 |
|---|---|---|---|
| **亮度分层（主）** | 敌我双方的环境 albedo 都在低饱和暗区间；识别靠"谁在发光"——EN 绿=自己的能量、Coral 红=敌方/Coral 系、等离子青白=高能 | `MaterialExParam` 把 `CoralExplosion_*`、`CoralWave_*`、`Coralwater_*` 做成专用着色；`HitEffectSfxConceptParam_Concept` 的攻击属性枚举含 `EN緑 / コーラル / パルス / レーザー / プラズマ` | B |
| **两段命中概念** | 攻击属性 ×（汎用着弾 / 重鉄 / 盾エネルギー）三态——**"打没打动"由特效本身区分**，不靠血量条 | `HitEffectSfxParam` + `Concept.tdf`；铁⇒盾エネルギー只用 2 个 SFX ID（低变化、高辨识） | B |
| **轮廓/预警** | 护盾命中是独立的能量波纹（`汎用バリア着弾(160)`、`PA_敵大_白_被弾波紋(630-660)`、`PA_敵特大_コーラル_被弾波紋(670-700)`）——**玩家一眼知道"这是打在盾上还是打在装甲上"** | Concept.tdf | B |
| **颜色编码** | 5/6 通道涂装（`Color_Main/Sub/Support/Optional/Joint/Device/Eye`）本身也服务可读性：玩家可以把自己涂成最显眼的颜色，这是**把可读性的一部分外包给玩家** | `MaterialExParam`；`PlayerColoringPresetParam` | B |
| **特效层级 + 频率闸门** | `playCategory / playPriority`；`HitInsDamageNearSfxNumMax=1` + `HitInsDamageNearSfxDist=50 m` + `BulletMultiFrameHitSfxIntervalTimeSec=0.2 s` | §4.1 / §8 | B |
| **抖动渐隐** | 用抖点而非半透明做渐隐，避免半透明排序错误导致的"看不穿" | `MaterialExParam.DitherFade / Translucent_Fade_Int` | B |
| **像素剔除** | 小/远景发光体做 pixel kill，防止一堆小亮点糊掉画面 | `PixelKill / VR_PixelKill / VR_PixelKill_Geom` | B |
| **中心留白** | 径向模糊的 `CenterThin` | §5.2 | B |
| **UI 色彩表** | `MenuColorTableParam` 882 行 × 4 字节（配色令牌化） | 实测行数 | B |

**TA 可复用原则**：
> 在"高速 + 大量粒子 + 复杂背景"的场景里，**颜色编码是最后一道防线，不是第一道**。优先用 ①亮度差（自发光 vs 无自发光）②轮廓（盾/装甲/破坏的波纹不同）③时间闸门（避免反馈堆积）④空间留白（屏幕中心不糊）。这四条都做完了还不够，再考虑加颜色编码——因为颜色编码一旦加多，背景的色调设计就被绑死了。

## 8. 性能策略：60 fps 的取舍（本报告证据最强的一节）

### 8.1 ★ `LoadBalancerParam`（33 行 × 80 字节）——引擎级动态画质阶梯

**字段（paramdex 实测）**：
`lowerFpsThreshold / upperFpsThreshold / lowerFpsContinousCount / upperFpsContinousCount / downAfterChangeSleep / upAfterChangeSleep` + 19 个 u8 画质项：

**行 ID 语义（Developer Names 实测原文）**：`0 PS4 / 1 XboxOne / 2 Win64 / 3 XboxOneX`；`10-13 各自平台的影片播放`；`20-23 对战`；`30 PS5 画質優先モード / 31 PS5 パフォーマンス優先モード / 32 PS5 レイトレモード / 33-35 对战版`；`40-45 XSX`；`50-55 XSS`；`100-103 过场播放`。

**这张表教给 TA 的六件事**：
1. **降级对象是"引擎模块"，不是"画质预设"**：19 个开关全部是可独立升降的数量/质量档，而不是 Low/Med/High 三档预设。
2. **迟滞必须是不对称的**：降要快（5 帧）、升要慢（20 帧），否则画面会在阈值附近反复抖。
3. **冷却帧数也是一种预算**：降档后 30 帧不再降（防止一次卡顿连锁降到底），升档后 10 帧不再升。
4. **对战模式更激进**：降阈值判定只要 3 帧、冷却只有 15 帧（对战容不下掉帧）。
5. **过场反而降"动态分辨率"**：过场是固定镜头的，可以接受动态分辨率（因为运动少、重影不明显），却把级联 0 阴影分辨率减半（因为镜头给的特写多、远景少）。**这是非常"懂"的一条**。
6. **能一眼看出哪些是"贵"的**：`sfxDistortion`（扭曲 = 全屏抓帧 + 二次采样）在 PS4 类平台上只有 4；`shadowCascade0ResolutionHalf` 是唯一一个"分辨率"级别的阴影开关；`MotionBlurIteration` 单独一档说明**多次递归模糊是主要成本**。

### 8.2 光追的真实用法（`GraphicsConfig_RaytracingQuality`，paramdex 定义字符串）

```
enabled / dirLightShadowEnabled / aoEnabled
dirLightShadowRaySampleScale / dirLightShadowRaySampleOffset
aoRaySampleScale / aoRaySampleOffset / dirLightShadowConeScale
```

**结论**：本作的光追只用于 **平行光阴影 + AO**，**没有光追反射**（反射由 `GraphicsConfig_ReflectionQuality` 的 `ssrEnabled / ssrGaussianBlurEnabled / ssrDepthRejectThresholdScale / ssrRayTraceStepScale / ssrFadeToViewerBias / ssrFresnelRejectBias / resolutionDivider=2 / localLightEnabled` 承担）。这解释了 `ChrModelParam.isNoRayTracing = 0`（62/62 行）——因为要在阴影/AO 里出现，所有角色都必须注册进光追场景。**这是"用光追补短板（接触阴影）而不是炫技（镜面反射）"的务实取舍。**（B，字段名为 A 级定义）

### 8.4 TA 会怎么砍（按优先级排序，均有数据支撑）

1. **先砍屏幕空间效果**：`sfxDistortion`（扭曲）→ `sfxWaterInteraction` → `postProcessDOF` → `postProcessLightShaft`。理由：这些是"氛围"不是"信息"。实测 PS4 类平台 `sfxDistortion = 4`（近关）。
2. **再砍粒子数量与密度**：`sfxParticleHalf`（实测 5↔13，约 2.6 倍跨度）+ `GraphicsConfig_EffectQuality.fNumOnceEmitsScale（默认 0.9）` + `fEmitSpanScale（默认 1.1）`。**注意"单次发射数量"和"发射间隔"是两个独立旋钮**——降密度比降数量更不容易被看出来。
3. **砍粒子的空间覆盖而非粒子本身**：`fLodDistance1..4Scale`（默认各 0.9）——**四段粒子 LOD 距离都可缩放**，即"远处粒子提前消失"。
4. **砍运动模糊的迭代次数**（`postProcessMotionBlurIteration` 单独一档），而不是关掉运动模糊。
5. **砍 Bloom，保住 Glow**（实测永不降 `Glow`）。
6. **最后才上动态分辨率与阴影分辨率减半**（`dynamicResolution` / `shadowCascade0ResolutionHalf` 只在过场与兜底时动）。
7. **绝不动**：`AA`（锯齿一眼可见）、`Glow`、`sfxGlow`（信息通道）、`SFX反射`（命中反馈的"空间感"）。

### 8.5 60 fps 的另一面：帧预算的"数据化"

`LoadBalancerParam` 的 30.60 vs 60.60 阈值是一份**明写的目标帧率声明**：PS5/XSX/XSS 有"画质优先（30）"与"性能优先（60）"两套，PS4/XB1 世代只有 30 fps 档（rid 0-3 全部 `lowerFps=30.60`）。主机 60 fps 的取舍**不是"哪个效果更好看"，而是"这一档位允许哪些项掉到什么级别"**。

## 9. 分析三问

### 9.1 如果把饱和度整体拉高 30%，会怎样？

**先看这个改动会作用在哪一层**：AC6 的色彩分两类——
- **环境色（低饱和）**：由天空盒资产（`SkydomeAssetParam` 47 行时段化资产）+ 环境 albedo 决定；
- **能量色（高饱和、高亮度）**：由 emissive 系列参数（`Device_*`、`Parts_Emissive`、`CoralExplosion_*`、`Laser_Threshold`）决定。

**拉高 30% 的连锁后果（C 级推断，机制清晰）**：
1. **金属失去金属感**。金属的固有色来自环境反射——环境一旦被染成"黄得更黄、蓝得更蓝"，所有金属件的反射会跟着变彩。物理上这是错的（金属 albedo 应当接近黑/中性），视觉上会从"工业金属"滑向"塑料彩涂"。
2. **可读性下降**。AC6 的敌我/状态识别里，颜色是"最后一道防线"（§7）。环境饱和度一涨，能量色与环境色的饱和度差被压缩，`EN 绿` 与沙尘黄、`Coral 红` 与爆炸橙开始争同一色相带。
3. **自发光反而变"不亮"**。感知亮度是相对的（tone mapping 后），环境整体变艳会抬高中间调，`Glow` 的对比优势被吃掉。
4. **雾/体积光被染色**（`fogVolume*` 系列继承场景色），远景层次会变糊。

**更好的替代方案**：不动 albedo 饱和度，改 `Emissive_Strength / Emissive_Power / [A_C]_Emissive_Glow_Int / Laser_Threshold`。理由是 AC6 的可读性主要靠**亮度差**而不是**饱和度差**（§7），而自发光通道有独立参数、不污染环境。
**设计空间边界**：饱和度 +30% 大致相当于把参数表里的色彩从"环境低饱和 + 能量高饱和"压成"整体中饱和"——**这不是调色，而是把两套通道的用途混成一套**，是结构性的破坏而不是风格性的调整。

### 9.2 如果去掉所有后处理，会怎样（干净但失去什么）？

**先分清"后处理"的边界（这是 TA 面试常考点）**：
- **不属于后处理**：延迟贴花（`useDeferredDecal = 247/248`，走 G-buffer）、PBR 直接光照、粒子几何、UI。
- **属于后处理**：Bloom、Glow、AA、SSAO、DOF、MotionBlur、LightShaft、ToneMapping、ZoomBlur、体积雾的上采样。

**失去清单（按损失严重度排序）**：

| 序 | 失去 | 具体后果 | 数据支撑 |
|---|---|---|---|
| 1 | **Tone Mapping** | HDR 线性直出会过曝；AC6 的动态范围跨"正午冰原 ↔ 深夜地下 ↔ 厂房内"，没有 tone mapping 就没有统一的中灰锚点，地下场景黑到不可读 | `LoadBalancerParam` 把 tone mapping 相关项列为基础层（从不降级） |
| 2 | **Bloom / Glow** | 推进器、激光、Coral 的"体积感"消失，只剩小色片。**能量武器的功率感是核心战斗反馈通道**，这等于砍掉一条信息通路 | `Glow` 档位在所有平台都是 21 |
| 3 | **AA** | 大量细长几何（天线、散热片、脚架）+ 高速运动 → 严重的爬行与闪烁 | `GraphicsConfig_AAQuality` 甚至保留 `forceFXAA2` 兜底 |
| 4 | **Motion Blur / ZoomBlur** | 高速机动的速度感只剩相机位移 + FOV 变化；QB 的"爆发瞬间"没有了 | `Zoomblur` 表 6 行情境配置全部失效 |
| 5 | **SSAO** | 关节、装甲缝、脚与地面的接触失去接地感，机体看起来"飘" | `GraphicsConfig_SSAOQuality` |
| 6 | **体积雾上采样** | 沙尘/厂房的空气感消失；远景层次断裂，巨型结构会显得"贴图糊" | `GraphicsConfig_VolumetricEffectQuality` |
| **反而变好** | — | 画面变干净、输入延迟下降（TAA/运动模糊都会增加延迟）、高速运动看得更清楚 | — |

**最重要的结论**：`GraphicsConfig_*` 把这一切拆成 15 个各自带 `enabled` 的模块，并且 `LoadBalancerParam` 给了它们**独立的降级档位**——**引擎从设计上就不认为后处理是一条固定管线，而是一组可插拔的感知层**。这直接告诉我们：TA 做后处理时不要做"漂亮的一套管线"，要做"可分级的一组模块 + 一个会自动谈判的调度器"。

### 9.3 如果不用自发光只用反光，会怎样？

**物理层面**：金属反射的值上限 = 环境亮度。AC6 的夜间、地下、厂房内环境光极暗（`SkydomeAssetParam` 有专门的 `夜ver1 / 深夜B(05:00)` 资产），反射在这些场景里几乎不产生可见信号。
**后果**：
1. **推进器/Coral/充能武器在暗场景里几乎不可见**——而"机甲在黑暗中只看得见几处红光"正是本作最具辨识度的画面语言。
2. **武器状态失去可视通道**：充能/过热/冷却/护盾剩余都靠发光表达（`Flickering_*` 6 通道、`Device_Effective_Range_Int`）。失去自发光 = 这些状态必须回到 UI，玩家视线被迫离开战场。
3. **性能反而更贵**：要看到反射，要么上 SSR（`GraphicsConfig_ReflectionQuality`：`ssrEnabled` + `resolutionDivider=2` + `ssrRayTraceStepScale`），要么上反射探针/CubeMap，两者都比"逐像素加法 + 半分辨率 Bloom"贵得多。**自发光是"用最廉价的逐像素运算买到最高的感知亮度"**——这是一个投入产出比极高的选择。
4. **AC6 并没有放弃反光**：它保留了完整的反射链（`ReflectionQuality` 的 `enabled / localLightEnabled / ssrEnabled / ssrGaussianBlurEnabled / resolutionDivider=2 / localLightForceEnabled`），但定位是**"金属质感的可信度"**，不是"能量信息"。

**结论**：**自发光是信息通道（状态/可读性/力量感），反光是材质通道（真实感/物理正确）。二者不可互替。** 一个只有反光的机甲游戏，在暗场景里就是一堆看不见的黑块；一个只有自发光的机甲游戏，机甲看起来像霓虹塑料。

## 10. TA 转化：两个效果的"复刻方案书"

### 10.1 ① 推进器尾焰 + QB 残影（UE5 / Niagara）

**一句话方案**：**不要做一个尾焰特效，要做"每个挂点一条参数行"的挂点系统** —— AC6 的 `ThrustersParam_PC`（103 行 × 700 字节）就是这么做的：每行（一套推进器）含 `main / subFront / subBack / subLeft / subRight / qbFront / qbBack / qbLeft / qbRight / lift / tankFront` 等十余个挂点，每个挂点独立 `SFXID + SlotNO + Scale + IsFollowDmyPoly + IsEraseActionEnd + IsHorizontal + camouFlageShow`。**`SlotNO`（管理スロット番号）是全局并发槽位号**——这是控制"同一帧能同时存在多少个尾焰实例"的闸门；`IsEraseActionEnd` 让动作结束即删特效（不用等粒子寿命）；`IsFollowDmyPoly` 决定特效是否跟随骨骼。残影侧：AC6 给"幻影"独立的 LOD 类型（`PartsDrawParam_LodType.tdf` 的 `幻影=10`）和独立的绘制距离缩放档（`LoadBalancerNewDrawDistScaleParam` 的「幻影」行），**说明残影走的是低配绘制通道，不是复制一个完整角色**。

**节点/步骤清单**：
1. **模型侧**：在 Booster/腿部骨骼上打命名 socket（对应 dummypoly），命名规范 `THR_Main / THR_QBFront / THR_QBL / THR_SubR …`。（复用 AC6 的挂点命名思路）
2. **Niagara 尾焰**：`Spawn Rate` 由推力曲线驱动 → `Velocity` 沿 socket 法线 → `Ribbon/Mesh Renderer` 做长拖尾 → 材质用 `Emissive + Refraction`（对应 `distortionEnable`）。
3. **QB 残影**：**不要 spawn 第二个 AC**。用两组 Mesh 快照（间隔 = QB 时长的 1/3~1/2），材质走 `Translucent + Phantomemission`（对应 AC6 参数名 `Phantomemission`），并置于独立的渲染层，在 LoadBalancer 等价的画质档里可整层关闭。
4. **径向模糊**（后处理）：按动作切三档 —— 普通 boost `Offset 0.0025 / CenterThin -1.0 / Alpha 140`；大 QB `Offset 0.005 / CenterThin -0.1 / Alpha 255`；高速移动 `Offset 0.020 / CenterThin -0.5`。并在 100 km/h 以上才开始插值，插值时间 0.4 s（对应 `ZoomBlur_ThresholdSpeedKmH=100 / InterpolationTime=0.4`）。
5. **性能闸门**：给尾焰设全局并发槽位上限（对应 `SlotNO`）；在画质档里暴露 `ParticleHalf` 级别开关；把"注册进缩小缓冲的特效距离"做一个可缩放倍率（对应 `sfxScaleRenderDistanceScale`）。

**性能注意点**：尾焰是 fill-rate 杀手（多挂点 × 持续发射 × 半透明叠加）。AC6 的三道保护是 ①槽位并发上限 ②独立的 `sfxParticleHalf` 档位（实测 5↔13）③按 4 段 LOD 距离提前消失（`fLodDistance1..4Scale`）。
**可复用性**：直接套用到任何"多推进器载具"（飞行器、机甲、飞船）；槽位 + 参数行的结构是通用的。

### 10.2 ② 命中火花与爆炸的分级反馈（数据驱动矩阵）

**一句话方案**：**把"命中特效"做成一张二维查询表，而不是一堆 if-else** —— AC6 有 `HitEffectSfxConceptParam_Concept.tdf` 定义"概念"（攻击属性 × 目标材质），再由 `HitEffectSfxParam`（71 行 × 240 字节）把每个概念展开成 **25 个 SFX ID**（斬撃/刺突/打撃/爆風/弾丸 × S/M/L/LL/LLL）。实测：`铁⇒汎用着弾`（rid=10）使用 `201000–201009` 共 10 个不同 ID，而 `铁⇒盾エネルギー`（rid=30）只复用 `990902 / 990903` **2 个 ID** —— **金属面命中做满 5 档，能量盾面命中主动复用**，美术预算被明确投在玩家可视度最高的通道上。爆炸还要再乘一个"地表材质"维度（同 TDF 的 300–470：煙 / 煙＆がれき / 石片 / 土 / 木片 / 砂 / 炎 / 氷 / 雪 / 電気 / ガラス / 水 / 沼 / 肉 / 布 / ラバー）。**而且必须配频率闸门**：`HitInsDamageNearSfxNumMax = 1`、`HitInsDamageNearSfxDist = 50 m`、`BulletMultiFrameHitSfxIntervalTimeSec = 0.2 s`。

**节点/步骤清单**：
1. **建表**（DataTable / CSV）：行 = `Concept（属性×材质）`，列 = `AttackType(5) × Tier(5)` → `SFX Asset`。**先把表建出来再谈美术，表结构决定了美术要做多少个资产。**
2. **概念枚举**：至少要有 `{铁, EN能量, 能量护盾, 实弹重甲, 爆炸, 地表材质×N}`。AC6 在这之上还加了 `パルス / レーザー / プラズマ / コーラル / アサルトアーマー / スタン / 初期ガード / AssetPA / 敵PA被弾波紋`。
3. **三级颗粒**：①火花（撞击点小粒子 + 短暂闪光）②碎片/材质碎屑（按地表材质换 mesh/贴图）③冲击环（护盾命中用波纹 Quad，装甲命中用烟尘）——**"打在盾上还是打在装甲上"必须一眼可辨**。
4. **频率闸门**（这一条比美术更重要）：近失 SFX 半径内最多 1 个；多段命中 SFX 最小间隔 200 ms；同一位置的重叠贴花走削除策略（`thinOutMode = 0 削除`，实测 248/248 行）。
5. **贴花**：弹痕用延迟贴花（`useDeferredDecal=1`）、按武器分型、寿命 10 s（实测 800000–800007 行 `lifeTimeSec=10.0`，与 `GraphicsParam.PaintDecalFadeOutTimeSec=10.0` 同值）、六通道材质 `mask/diffuse/metallic/normal/height/emissive` + 3 个标量 `maskScale/metallicScale/siniScale`。**AC6 明确不用 POM（实测 0/248）。**
6. **爆炸**：按地表材质分支 + 按"是否打在 PA/护盾上"分支（`480–530 Asset PA`、`630–700 PA 敌大/特大 × 白/コーラル 被弾波紋`）。

**性能注意点**：同时命中的数量在高射速武器下会爆炸式增长。三道闸门 = ①数量上限（50 m 内 1 个）②时间间隔（200 ms）③贴花削除 + 寿命。**先做闸门，再做美术**——否则你会在优化阶段被迫砍掉一半美术量。
**可复用性**：任何"打击感"驱动的游戏（动作、射击、机甲）都能直接套这个"概念矩阵 + 频率闸门 + 贴花分级"三件套。
