### 1.2 四段式解读

**设计意图**：前 30 分钟同时完成三件事——①教会"移动/锁定/射击/修理/QB/AB"六个动作；②让玩家以**固定残破机体**（本关不可用其他 AC 重打，Wiki 备注 B）体验"弱机体也能赢"，避免第一小时就出现装配焦虑；③用一个**确实会死人的 Boss** 建立"这游戏会考你"的心理预期。
**实现手段**：所有"教学点"都在同一张 `TutorialParam` 里，靠 4 个 `Keyguide*_ActJudgeParamID` 槽绑定动作谓词；`MenuResourceType` 决定它是 toast 还是时停弹窗。
**玩家体验/结果**：0–19 分钟教学密度极高（1401 段 30 行里 19 行挂 KeyGuide，占 63%），19–27 分钟**主动撤掉教学**——这是刻意的"放手"。
**可复用结论**：**"前 20 分钟密集判定式提示 → 主动静默 5 分钟 → 在失败点补一发针对性弹窗"** 是一套可直接迁移的三段式节奏模板，比"全程弹窗"或"全程不管"都更省认知预算。

### 2.1 四因子的教学预算（可实测的代理指标）

把 201 行教程按 ID 段落归类（分类本身是 C 级判断，**行数是实测**）：

| 1506 / 1509（考试 / 特殊） | 2 | ③装配 | 时停 2 |

→ **投放结构本身给出的权重**：任务内/战斗操作向 **122 行（60.7%）**，装配/系统向 **72 行（35.8%）**，考试/败北专属 **6 行（3.0%）**。

### 2.2 难度四因子占比估计

| 因子 | 前期（第 1–2 章） | 后期（第 4–5 章） | 依据 |
|---|---:|---:|---|
| ①操作精度（QB 时机、EN/负重管理、空中作业） | 20% | **35%** | 重力 120 m/s²（12g，引自 P6，本报告未复现）→ 空中停留本身是操作负担；QB 无无敌帧（引自 P2）→ 闪避靠位移不靠帧 |
| ②认知负荷（读招 / 信息处理） | 30% | 30% | 敌人有完整的感知模型：`AwarePointMax=100`、衰减 `20/s`、`ShareTargetTime=0.2s`、`assignAttackRoleBattleRange=250m`、`addImpactDisableTimeSec=2.0`（实测）；读招成本恒定 |
| ③装配决策（机体构筑与任务匹配） | **40%** | 25% | 前期**唯一**能改变结果的自变量（部件少→组合清晰）；后期部件爆炸式增长，决策成本仍高但被操作弥补 |
| ④资源管理（弹药费 / 修理费 / EN / OST 点） | 10% | 10% | 结算侧成本上限被钉死（实测 cap 200000）；EN 归入① |

**主要矛盾 = ③装配决策 ↔ ①操作精度的可互换性**。这不是"哪个更难"，而是"游戏允许你用装配把操作难度买下来"：
- 前期操作精度不足 → 换坦克腿 + 双加特林/双霰弹，用稳定性和 DPS 覆盖操作失误；
- 后期操作精度成型 → 轻量双足 + 高机动，用位移替代耐久。
- 这个换算之所以成立，是因为**姿态稳定（`stability`，EquipParamProtector @488）**与**冲击力/累积冲击（`impactPower` @528 / `residualImpactPower` @988）**是同一套数值（引自 _shared.md 已核验字段表）；稳定值高 → 不易被打断；冲击力高 → 容易打出硬直。
**反面**：当装配破解不了某个机制时（如 `3230 Destroy the Ice Worm` 这类机制型 Boss），换算链路断裂，玩家会突然感到"难度暴涨"——这就是**墙**的来源。

> 这四条占比是 **C 级估计**。证伪方法：抓取社区"卡关求助帖"的归因分布（换装建议 vs 操作建议 vs 策略建议），按关键词计数；本报告未做此统计。

## 3. ★ 教学系统

### 3.1 分发方式：三条管道，一张表

| 管道 | 触发方式 | 数据结构 | 行数 | 打断性 |
|---|---|---|---:|---|
| **A. KeyGuide 轻提示** | 被动触发（玩家做出/需要做出某动作） | `MenuResourceType=2`（トースト：キーガイド） | 51 | 不打断（HUD toast） |
| **B. 时停弹窗（Time stop）** | 被动触发（进入区域/首次遭遇/首次成功） | `MenuResourceType=105`（モーダル：ムービー(インゲーム用)） | 91 | 打断（暂停 + 图文/影片） |
| **C. 前端教程 / 解禁公告 / 档案库** | 主动查阅 + 系统派发 | `MenuResourceType=100/101`；`MenuBehaviorParam` 把每个前端画面绑一个 `tutorialID` | 72 | 不打断（菜单内） |

补充两条**非 TutorialParam 的投放通道**（实测）：
- **读盘期投放**：`KnowledgeLoadScreenItemParam`，5 行 × 28 字节，字段 `unlockFlagId / invalidFlagId / msgId`，**5 行全部为 `-1 / -1`**（即永远可显示），`msgId = 10000–10004`，对应 5 个地点知识卡（Bering Special District / PBA / Shell Plant / Bayram Industry / Central Ice Field）。paramdex 对该字段的日文说明原文可查（见 §11）。→ **引擎具备"按事件旗标门控读盘知识卡"的能力，但 vanilla 一行都没用**。另有 `MissionParam.loadingScreenImageID` 全剧情任务统一为 `10000`（同一张图），`loadingScreenTextID` 全为 `0`。
- **档案库（ARCHIVES > TIPS）**：`UnlockParam_Archive_Tips` **114 行 × 16 字节**，`unlockType` ∈ {2=イベントフラグ 59 行, 5=ミッションクリア 55 行}。这是**教学知识的可检索长期存储**，也是"教学投放量"最硬的计数口径。

### 3.2 ★ 行为判定式教学：机制与价值

**（1）这是什么**

`TutorialActJudgeParam` 每行 9 字节，字段实测为：

| 偏移 | 类型 | 字段名（paramdex） | 日文显示名 |
|---:|---|---|---|
| 0 | u8 | `State0_ActionSlot` | スロット |
| 1 | u8 | `State0_ActionType` | 行動タイプ |
| 4 | u8 | `State1_ActionSlot` | スロット |
| 5 | u8 | `State1_ActionType` | 行動タイプ |
| 8 | u8 | `ExtActionType` | 拡張行動判定 |

枚举定义（`Tdfs/*.tdf`，Shift-JIS 解出，实测）：

- `TUTORIAL_ACTJUDGE_SLOT_TYPE`：0 无 / 1 本体 / 2 右手武器 / 3 左手武器 / 4 右背武器 / 5 左背武器 / 6 アイテム
- `ACTION_FE_STATE_TYPE_ENUM`：1 ジャンプ / 2 上昇ブースト / 3 クイックブースト / 4 修復 / 5 ブースト移動 / 6 アサルトブースト / 7 大ジャンプ / 8 AB 停止 / 30 ドリフト / 31 ホバリング / 100 チャージショット / 101 リロード / 102 ガード / 103 ブレード / 104 ブレードコンボ / 105 チャージブレード / 106 攻撃 / 116・117 チャージ中断
- `TUTORIAL_EXT_ACTJUDGE_TYPE`：1 右背ミサイルでマルチロック射撃中か / 2 ロック対象を切り替えたか / 3 ロックアシストモードを切り替えたか

**逐行解码出的 31 条谓词，本质是一套"动作组合 DSL"**。举三条最能说明表达力的：

| 判定 ID | 语义 | State0 | State1 | Ext | 读法 |
|---:|---|---|---|---:|---|
| 22 | ダブトリ（双扳机） | 右手武器 · 106 攻击 | 左手武器 · 106 攻击 | 0 | **双手同时开火** = 两个 `(槽,类型)` 同时成立 |
| 102 | 右手：ガード攻撃 | 左背武器 · 102 ガード | 右手武器 · 106 攻击 | 0 | **盾击** = 左手盾在防御态 **且** 右手在攻击 |
| 122 | 右背：多锁导弹攻击 | 右背武器 · 106 攻击 | — | 1 | 普通攻击 **且** 扩展判定"右背导弹正在多锁射击中" |

**（2）它比"读弹窗"强在哪里**

| 维度 | 读弹窗式教学 | 行为判定式教学 |
|---|---|---|
| 验证 | 玩家点"确定"= 跳过 | 玩家**必须实际执行**该动作组合，判定才通过 |
| 时机 | 只能在预设节点弹 | 可在"玩家已具备条件但还没做"的瞬间提示（`1401010` 只在需要 Boost 移动时挂提示） |
| 粒度 | 一段文字 | 可精确到"左手武器 / 充能攻击 / 蓄力中断"这一级（31 个谓词） |
| 复用 | 重写文案 | 同一谓词被 128 次引用（实测），改一处即改全部挂载点 |
| 失败反馈 | 无 | 玩家做出动作 → KeyGuide 消失 = **隐式的正反馈**（不做出来就一直在） |

**（3）关键工程细节：9 字节不是 bug**

`python tools/param_inspect.py --selftest` 报"3 个异常"，异常样例正是 `van/ mob/ reibis/ TutorialActJudgeParam.param`（三平台各一份）——因为自检脚本按"行宽必须能被 4 整除"筛选。而 **paramdex 独立计算出的结构大小是 9 字节，与实际 31 行 × 9 字节 `SIZE MATCH`**。也就是说 `9 % 4 = 1` 是真实结构（5 个 u8 字段 + 2 处各 2 字节的 `dummy8 reserve`），**不是解析器 bug**。

### 3.3 教学与实战的衔接

- **学完立刻用得上**：KeyGuide 只挂在"当前可执行"的动作上（如 `1401140 → repair` 挂在"你已受伤"的场景）。
- **学完有地方练**：7 关 TRAINING（`missionType=3`：Basic Controls / Combat Fundamentals / Assembling an AC / Reverse-Jointed / Tetrapod / Tank / Advanced Mercenary Certification），且**按档案库的解锁条件反推，训练关就是配套教材**（实测 `UnlockParam_Archive_Tips`）：
  - 清 `9200 Beginner Training 1` → 解锁 5 条（Lock-on / Reloading / Missile Lock / Melee Weapons / Wall Hack Radar）
  - 清 `9201 Training 2` → 9 条（ACS Accumulative Strain / Critical / Assault Boost Attacks / Surprise Attacks / Shield Defense / Attack Indicators & Initial Guard / Canceling Actions…）
  - 清 `9202 Assembling an AC` → 5 条（Double Trigger / Boosters & Mobility / Generators & Basic Specs / FCS & Engagement Distance / AC Assembly & Strategy）
  - 清 `9203 Reverse-Jointed` → 6 条；`9204 Tetrapod` → 3 条；`9205 Tank` → 2 条
- **学完可以回查**：114 条档案条目 = 永久可检索。

**四段式**：意图 = 把"教学"从"消耗注意力的过场"变成"玩家自己的操作证据 + 可回查的档案"；手段 = 谓词化判定 + 三形态 ID + 档案解锁条件；结果 = 提示可以在最相关的那 0.5 秒出现，也可以在菜单里静默存在；复用 = **任何有"动作状态机"的游戏都能照抄这套 `(槽, 动作) ∧ (槽, 动作) ∧ 扩展` 的谓词表**。

## 4. 卡关的官方解法路径：换装 → 换武器 → 换策略 → 提高操作

**为什么"换装"排第一**——三条设计意图：

1. **它是唯一在失败画面之后还能立刻执行的动作**。死亡 → 返回车库/装配屏是一条零成本路径（失败不扣钱，见 §6）；而"提高操作"需要分钟级的重复练习。
2. **它把失败归因从"我手笨"改写成"我配置错了"**。这是留住新手的核心心理机制：前者伤自尊且不可控，后者是**可解谜题**。数据侧最直接的证据：`1601000 Tutorial: The Right Assembly for the Job` 的触发条件是**在 `2030 Operation Wallclimber` 中失败**，内容却讲装配。
3. **它消耗的是玩家已有的资源**（COAM + 已解锁部件），形成一个正反馈闭环：打不过 → 换装 → 需要钱 → 回去打副任务/竞技场 → 部件解锁（`UnlockParam_Equipment` 24 行：15 行挂傭兵ランク 1–15、5 行挂竞技场击破、4 行挂指定任务通关）。

**顺序为什么不能倒过来**：如果把"提高操作"放第一，等价于承认"这个 Boss 只能靠练"，会把中等水平玩家直接筛掉；而"换策略"（读招、走位套路）需要先有能执行策略的机体（比如需要足够的 EN 或载重才能持续滞空）。

> 这个顺序**不是玩家手册上的明文，而是从数据与社区解法反推的设计意图（C 级）**。反证条件：如果多数玩家的实际解锁序列是"先练操作再换装"，该结论不成立——可用通关录像的首杀尝试次数与装配变更次数做编码验证。

## 6. 失败成本

| 成本项 | 量级 | 证据 |
|---|---|---|
| **时间** | 死亡 → 回检查点/重开任务，回到战斗的等待主要是读盘；Boss 尝试一次 2–5 分钟 | A/B（检查点机制社区一致；`Supply Stations` 同时补充弹药与修理包） |
| **金钱（弹药 + 修理）** | **失败不结算**；只在**任务完成**时从报酬里扣。公式侧：`bulletCost_rate=1.0`、`bulletCost_limit=200000`；`repairCost_coefficient=2.0`、`repairCost_limit=200000`（60 个 `chater≥1` 的剧情行中 58 行为该配置；**例外只有 `4200 Escape`（脱狱，另一关固定机体任务）`0.0 / 0.0 / 0 / 0`**，以及一行越界测试 ID `99990022`（修理系数 0.5）） | 实测 + B |
| **进度损失** | 无（任务内检查点 + 车库进度永久） | A/B |
| **评价损失** | 有（S/A/B/C 分档由受伤害、弹药费、击杀、时间加权；`calcScoreCoef_*` 与 `calcRankThreshold_RankS/A/B/C` 实测存在于 MissionParam） | 实测 |
| **竞技场 / 训练** | `baseReward=0`、`maxClearTime=0` → **完全不进结算**（免费练习场） | 实测 |

### 「低失败成本 + 高惩罚强度」的评价

**成立，且是有意的组合。** 拆开看：
- **高惩罚强度**（一次失误 = 掉 40% 血/被打出硬直/被秒）提供**紧张感与学习信号**——它让"读招"这件事有反馈。
- **低失败成本**（零金钱、零进度、可回检查点）提供**重复尝试的许可**——它让"练习"这件事没有沉没成本。
- 两者相乘得到的是：**惩罚注意力，不惩罚钱包和时间之外的东西**。若做成"高惩罚强度 + 高失败成本"，Boss 战会变成资源消耗战（玩家会为了省钱而不敢尝试新装配），**直接摧毁 §4 的"换装"解法路径**。
- 数据侧的呼应：竞技场/训练两套模式把 `baseReward` 与 `maxClearTime` 全部置 0，等于在系统层承认"这是练习场，不是经济系统的一部分"。

> **风险**：同一组合也让"资源管理"（难度四因子④）几乎失效——`repairCost_coefficient=2.0` 看起来很严厉，但因为有 `cap 200000` 且不随失败累积，实际上只影响评价等级，不影响生存。所以④在难度构成里只能给 10%（§2.2）。

## 7. 没有难度选项：得与失

### 7.1 玩家自主调节难度的五条通道

| 通道 | 具体做法 | 数据支撑 |
|---|---|---|
| ①**装配** | 换腿型/武器/推进器，直接改变操作容错率 | `EquipParamProtector.stability`@488、`AtkParam.impactPower`@528（引自 _shared.md 已核验表） |
| ②**训练与竞技场** | 7 关训练 + 42 行竞技场/模拟数据行，免费练 | 实测 MissionParam |
| ③**任务顺序** | 第 1–2 章多个任务可自由顺序做，先攒钱买件再打墙 | 社区任务表 B |
| ④**S 评价与 NG+/NG++** | 高难内容是可选的自我加压，不挡主线 | B |
| ⑤**操作系统（OST）** | 解锁多样化的机体能力（assault armor / terminal armor / weapon bay…） | `TutorialParam 2200–2213` 段（Tutorial: Assault Armor / Pulse Armor / Pulse Protection / Terminal Armor / Weapon Bay…）实测 |

### 7.2 排斥了谁

- **不愿意做装配优化的玩家**：他们面对的是一个"必须换装才能过"的关卡，但游戏**没有在关卡里给装配建议**（除了败北后的那一条弹窗）。对"我就想用喜欢的机体通关"的玩家，本作的答案是"不行"。
- **手速/反应有困难的玩家**：无难度选项 + QB 无无敌帧（引自 P2）+ 12g 重力（引自 P6），意味着**没有任何降低操作要求的全局开关**；唯一的替代是坦克腿这类"低操作高耐久"部件，而这需要玩家先理解装配系统。
- **视觉/听觉可及性需求者**（P10 实测，本报告未复现）：整个选项菜单 62 条属性里**没有字号设置、没有色盲模式**；字幕样式（`FeFreeDialogParam` 31 行含 `FontScale / FontColor / BaseRect / DisplayTime`）**数据表支持但未开放给玩家**。→ 这是"没开放"而不是"没做"，性质不同：**实现成本已经付过了**。

### 7.3 可及性批评是否成立

**部分成立，但要分开算账**：
- 成立的部分：**缺少可以零成本打开的辅助开关**（字号、色盲调色、更宽的输入窗口）。这些属于"已实现、未暴露"，属于明确的工程遗漏而非设计取舍。
- 不成立的部分：把"没有难度选项"本身当作可及性缺陷。因为难度调节通道（装配）在系统层是真实存在且强力的（§4、§7.1）。**批评的准确表述应该是"把难度调节藏进了一个需要元认知的系统里"**——玩家必须先意识到"我可以换装"，才能用上这个滑块。
- **数据上能看到的补救**：那三条败北教学（1601000 等）正是官方对这个缺口的补丁——**在玩家最需要"提示我可以换装"的时刻，用一次时停弹窗把这条通道指出来**。

## 9. 分析三问

### 问 1：如果加入四档难度选项会怎样？

- **正面**：解决 §7.2 的三类排斥；把"装配买难度"这条隐性通道显性化。
- **代价（结构性）**：AC6 的难度不是一个标量，而是**四个因子的耦合**（§2.2）。要做四档，必须为每档定义四组参数：敌人伤害/血量（②③）、敌人 AI 感知（`AwarePointMax`、`ShareTargetTime`、`assignAttackRoleBattleRange`——这些在 `EnemyCommonParam` 里是**全局单行表**，只能整体调）、弹药/修理系数（④）、玩家容错（维修包数量）。→ **改造成本 ≈ 重做一套数值分层**，而不是加个倍率。
- **更省的做法（C 级建议）**：不动战斗数值，只做**"装配建议系统"**——在墙上死 3 次后，弹药/修理系数下调 + 败北弹窗升级为带推荐装配的版本。这保留了"没有难度选项"的表达，同时补上了唯一的真实缺口（"我不知道可以换装"）。
- **定位设计空间边界（共享三问之②）**：把 `repairCost_coefficient` 从 2.0 放大 10 倍 → 20.0（但 cap 仍是 200000），结果是**只有超时/高消耗的玩家会破产**，失败者仍不破产；缩到 0.2 → 经济系统彻底消失，部件解锁节奏崩塌。→ **该参数的设计空间其实被 `cap` 锁死了**，能调的自由度远小于名字暗示的。

### 问 2：如果把教学全部改成强制弹窗会怎样？

- **立刻损失**：51 行 KeyGuide（`MenuResourceType=2`）的**"不打断"属性**。这 51 行是教学密度最高的一批（前 20 分钟几乎全靠它），强制弹窗会让序章从"边跑边学"变成"跑三步读一段"。
- **数据上能看到的证据**：全表 `RepeatType` 分布为 `{0 全局一次: 36, 1 每任务一次: 119, 2 不限次数: 46}`（实测）。教学系统**已经用 RepeatType 做了打断预算**：只有 36 行允许"全周目只弹一次"这种最高打断级别的设定，而 119 行是"每任务一次"（失败重打会**再弹一次**，等于救急）。强制弹窗等于把这 119 行全部升级为最高打断级别。
- **会丢掉的第二样东西**：**判定失败时的静默反馈**。KeyGuide 挂着动作谓词，做对了它就消失；强制弹窗没有"消失"这个状态。
- **代价最小的替代**：保留谓词判定，只把"未完成的 KeyGuide"在 **10 秒无操作后升级为时停弹窗**（分级升级），而不是一上来就弹。

### 问 3：如果取消竞技场会怎样？

- **损失 1（数据）**：42 行 `missionType=2` 的竞技场/模拟数据消失 → `UnlockParam_Equipment` 里 5 行"竞技场击破解锁部件"失效，`UnlockParam_NpAcArena` 的 41 行对手解锁表作废 → **部件解锁曲线被砍掉一段**，玩家在墙上能换的装变少。
- **损失 2（教学）**：档案库里 3 行（`UnlockParam_Archive` 的 2004000/2004100/2005000/2006000，`unlockType=4 傭兵ランク`）失去载体。竞技场是**唯一在"零资源消耗 + 零任务失败风险"下考你机体极限**的地方，删掉它等于删掉"换装"解法路径的验证场。
- **共享三问之①（删掉该机制）** 的等价问法：删掉竞技场不会让主线变难（主线难度不由它决定），但会让**"打不过 → 换装 → 先验证新装"这个循环退化成"打不过 → 换装 → 直接拿命去试"**，失败成本的时间部分立刻上升。

### 共享三问之③：它到底在解决什么问题？有没有更简单的替代方案？

- 解决的问题：**"如何在不让玩家读说明书的前提下，让玩家学会一套有 6 个自由度（本体/左右手/左右背/道具）+ 3 种射击模式 + 2 种近战模式的操作集。"**
- 更简单的替代方案 A：**强制新手关 + 弹窗**（很多动作游戏的做法）。为什么没用：AC6 的动作集合是**组合式**的（双扳机 = 左右手同时开火；盾击 = 左手盾 + 右手攻击），组合空间远大于"按 X 跳跃"，一次性灌输必然记不住。
- 更简单的替代方案 B：**只做档案库，玩家自己查**。为什么没用：档案库是"事后检索"通道，解决不了"我不知道有这个东西"的问题。
- 结论：**谓词化判定 = 用数据把"组合动作"枚举成有限个可检测状态**，这是唯一能把"组合式操作"变成"可教学单元"的做法。没有更便宜的替代。

| **⑥ 前端画面注册表** | "每个菜单画面首次进入弹对应教程" | 一张 `画面ID → tutorialID + 帮助菜单开关` 的表；**策划改表即可，不用改代码** | `MenuBehaviorParam` 31×32：`tutorialID`(s32)@0 + `enableHelpMenu`(u8)@4 |
| **⑦ 读盘期内容投放** | "读盘时投放世界观/知识卡" | 带**双旗标门控**的卡片表：`unlockFlagId`（满足即显示）/ `invalidFlagId`（满足即隐藏，优先级更高），`-1` = 无门控 | `KnowledgeLoadScreenItemParam` 5×28；paramdex 日文说明原文见 §11 |
| **⑧ 本地化** | 文案多语言 | **教程表里一个字都没有**——只有 `msgId` / `ImageID` / SE ID。全部文本在外部文本表（paramdex 对 `msgId` 的说明写着 `テキストID(Loading Text.xlsx)`） | 实测（TutorialParam 无任何字符串字段；`KnowledgeLoadScreenItemParam.msgId` 说明） |

**TA 具体做什么（给读者的落地清单）**：

1. **条件编辑器**：把 `(槽位, 动作类型) × 2 + 扩展` 做成一个下拉式 Editor 面板（策划选"左手武器/充能攻击"），底层序列化成 5 个 u8。**难点不是 UI，是槽位枚举与运行时动作状态机的对齐**——游戏里"左手武器正在充能"这个状态必须能被查询到。
2. **状态机与判定时机**：谓词求值需要处理"同时成立"（双扳机、盾击）与"持续中"（多锁导弹射空中）。本作用 `ExtActionType` 而不是加第三个 `(槽,类型)` 对，说明**设计师把"需要额外查询的状态"与"需要监听的输入"分开建了模**——这是一个很值得抄的边界划分。
3. **素材流水线**：82 个唯一 `ImageID` + SE ID + `msgId`，必须有导入校验（缺图标/缺文本/缺本地化要在打包期报错，而不是运行时黑屏）。
4. **存档兼容**：教学进度走通用事件旗标系统，因此**新增教程不需要动存档结构**——这是它能做到 201 行的前提。若把教学进度写成独立 bitfield，每加一条就要改存档版本号。
5. **不打断提示的 UI**：`MenuResourceType=2` 的 toast 要能同时显示最多 4 个按键图标（实测 9 行教程挂了 4 个 Keyguide 槽，其中 `1401122` 是 `QB / 右手射击 / 右背射击 / 光剑`）。→ **HUD 的 KeyGuide 组件必须支持 4 槽自适应排版**，这是很典型的一个"数据驱动出来的 UI 需求"。
6. **调试工具**：谓词表最大的风险是"策划挂了个永远不可能为真的组合"（例如"左背武器 + 充能攻击"）。需要做一个**静态校验器**：检查槽位与动作类型的合法组合（近战只能挂左手武器槽；多锁只能挂右背武器槽）。本报告的解码结果可以直接当成校验规则集。
